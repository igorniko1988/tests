# A0. Big-O и метод решения

**Смысл темы.** Big-O — способ ответить на вопрос «насколько медленнее станет программа, если
данных станет в 10 раз больше». На каждом лайвкодинге интервьюер спрашивает сложность решения,
а размер входа в условии подсказывает, какое решение от тебя ждут. Здесь же учимся видеть
скрытую сложность — одна безобидная строка внутри цикла превращает O(n) в O(n²) — и решать
задачи по одному и тому же методу из шести шагов. Это основа всего трека A.

## Как проходить

Для каждого раздела по порядку: читаешь `sNN_*/THEORY.md` → делаешь то, что в его блоке
«Практика к разделу» → пишешь в чат «готово A0 …». Все команды — из папки `a00_big_o`.

## Разделы

| № | Папка | Тема | Практика |
|---|---|---|---|
| 1 | `s01_what_is_big_o/` | Что такое Big-O, правила упрощения, вложенные циклы | drills |
| 2 | `s02_growth_classes/` | O(1), O(log n), O(n), O(n log n), O(n²), O(2ⁿ) | drills |
| 3 | `s03_python_ops/` | Цены операций list, dict, set, str, deque; амортизация | drills |
| 4 | `s04_hidden_cost/` | Скрытая сложность: O(n) внутри цикла | **t01** оцени сложность |
| 5 | `s05_memory/` | Сложность по памяти, обмен память ↔ время | — |
| 6 | `s06_input_size/` | Размер входа → нужная сложность | — |
| 7 | `s07_method/` | Метод решения задачи на собесе (6 шагов) | **t02–t04** ускорь решение |
| 8 | `s08_cheatsheet/` | Шпаргалка и вопросы собеса с ответами | вслух |

- **t01** — `uv run python s04_hidden_cost/t01_estimate.py` (сверит и объяснит).
- **t02–t04** — в файлах лежит рабочее решение в лоб за O(n²), перепиши в O(n).
  `uv run pytest -k t02`: тесты проверяют и ответ, и время (решение в лоб не уложится в 0,2 с).

`solutions/` — эталон, ключ к t01 и объяснения к упражнениям, не открывать до решения.
Прогнать тесты на эталоне: `SRC=solutions uv run pytest`.

Зачёт: t01 ≥ 8/10, t02–t04 зелёные + ревью (сложность до и после — в чат), вопросы собеса вслух.
