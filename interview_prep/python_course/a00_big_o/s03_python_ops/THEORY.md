# A0 · Раздел 3. Сколько стоят операции Python

[← раздел 2](../s02_growth_classes/THEORY.md) · [оглавление урока](../README.md) · [раздел 4 →](../s04_hidden_cost/THEORY.md)

**Простыми словами.** Одна строка Python может быть O(1), а может скрывать целый цикл.
`x in items` выглядит так же коротко, как `x in seen_set`, но первое перебирает весь список,
а второе отвечает сразу. Чтобы оценивать свой код, надо знать цену встроенных операций —
а для этого понимать, **как устроены** список и словарь.

---

### Как устроен list — массив ссылок

`list` хранит подряд в памяти **ссылки** на объекты (вспомни C1: в списке лежат не сами
объекты, а стрелки на них). Ячейки одинакового размера, поэтому адрес i-й ячейки вычисляется
формулой «начало + i × размер ячейки» — без перебора.

```
 индекс:    0     1     2     3     4    (свободно)(свободно)
          [ ●  |  ●  |  ●  |  ●  |  ●  |         |         ]
            │     │     │     │     │
            7    "a"   3.5  None   [ ]
```

Отсюда цены:

- **`lst[i]`, `lst[i] = x`, `len(lst)` — O(1):** адрес считается формулой, длина хранится в объекте.
- **`lst.append(x)` — O(1) амортизированно:** в конце обычно есть свободное место (см. ниже).
- **`lst.pop()` — O(1):** убрать последний — ничего не надо сдвигать.
- **`lst.insert(0, x)`, `lst.pop(0)` — O(n):** чтобы вставить или убрать **в начале**, все
  остальные n ссылок сдвигаются на одну ячейку.
- **`x in lst`, `lst.index(x)`, `lst.count(x)`, `lst.remove(x)` — O(n):** список не знает, где
  лежит значение, — сравнивает с каждым элементом по очереди.
- **`lst[a:b]` — O(b − a):** срез создаёт **новый** список и копирует ссылки.
- **`min`, `max`, `sum` — O(n)**, **`sorted`, `lst.sort()` — O(n log n).**

### Что значит «амортизированное O(1)» у append

Список заранее выделяет памяти **с запасом**. Пока запас есть, `append` просто кладёт ссылку в
следующую ячейку — O(1). Когда место кончилось, Python выделяет новый блок побольше (примерно
в 1,125 раза плюс немного) и **копирует** туда все ссылки — это O(n), но случается редко.

```
 append ×8:  [■■■■····] → [■■■■■■■■] → места нет → новый блок [■■■■■■■■········]
                                        копирование 8 ссылок — дорого, но редко
```

Если сложить стоимость **всех** n добавлений и разделить на n, получится константа на одно
добавление. Это и называется **амортизированная** сложность: отдельная операция иногда дорогая,
но в среднем по длинной серии — O(1).

### Как устроены dict и set — хеш-таблица

`dict` и `set` — это таблица ячеек. Для ключа считается `hash(key)` — число, — и по нему
вычисляется номер ячейки. Поиск идёт **сразу в нужную ячейку**, без перебора.

```
 hash("bob") % 8 = 5  →  ячейка 5
 ┌───┬───┬───┬───┬───┬────────────┬───┬───┐
 │   │   │   │   │   │ "bob" → 31 │   │   │
 └───┴───┴───┴───┴───┴────────────┴───┴───┘
   0   1   2   3   4        5        6   7
```

- **`key in d`, `d[key]`, `d[key] = v`, `del d[key]` — O(1) в среднем.**
- **`x in s`, `s.add(x)`, `s.remove(x)` — O(1) в среднем.**
- **Худший случай — O(n):** если у многих ключей совпадут номера ячеек (коллизии), придётся
  перебирать их цепочку. Со встроенными типами на практике не встречается, но на собесе
  хорошо сказать «O(1) в среднем, O(n) в худшем».
- **`x in d.values()` — O(n):** хеш-таблица построена по **ключам**, значения просто перебираются.
- **`set(lst)`, `dict(...)`, `Counter(lst)` — O(n):** построение — один проход с добавлением.
- **`a & b`, `a | b` у множеств — O(len(a) + len(b))** (пересечение — O(min) в среднем).

### Строки

`str` неизменяема (C1), поэтому:

- **`s[i]`, `len(s)` — O(1)**; **`ch in s`, `s.count(ch)`, `s.find(sub)`, `s.replace(...)` — O(n).**
- **`s + t` — O(len(s) + len(t)):** создаётся новая строка, обе копируются.
- **`s += ch` в цикле** — в худшем случае O(n²) суммарно (каждый раз копия растущей строки).
  CPython иногда это оптимизирует, но полагаться нельзя. Правильно — собрать части в список и
  сделать **`"".join(parts)` — O(n)**.

### deque — очередь с двух концов

`collections.deque` умеет **`append`, `appendleft`, `pop`, `popleft` за O(1)**. Если нужна
очередь (BFS, обработка задач по порядку) — бери `deque`, а не `list.pop(0)`.

### Шпаргалка цен

| Операция | list | dict / set | str | deque |
|---|---|---|---|---|
| доступ по индексу / ключу | O(1) | O(1) | O(1) | O(n) в середине |
| `x in ...` | **O(n)** | **O(1)** | O(n) | O(n) |
| добавить в конец | O(1)* | O(1) | O(n) (новая строка) | O(1) |
| добавить / убрать в начале | **O(n)** | — | O(n) | **O(1)** |
| удалить по значению | O(n) | O(1) | — | O(n) |
| копия, срез | O(k) | O(n) | O(k) | O(n) |

\* амортизированно.

---

**Частая ошибка.** Думать, что короткая строка кода — дешёвая. `if x not in result:` внутри
цикла, где `result` — список, превращает O(n) в O(n²). Подробно — в разделе 4.

<details><summary>Проверь себя: O(1) или O(n)?</summary>

1. `"admin" in user["roles"]`, где `roles` — список — **O(n)** по длине списка ролей.
2. `"admin" in user`, где `user` — dict — **O(1)**: проверка ключа.
3. `queue.pop(0)` у list — **O(n)**; `queue.popleft()` у deque — **O(1)**.
4. `5 in d.values()` — **O(n)**.
</details>
