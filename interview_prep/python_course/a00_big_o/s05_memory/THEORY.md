# A0 · Раздел 5. Сложность по памяти

[← раздел 4](../s04_hidden_cost/THEORY.md) · [оглавление урока](../README.md) · [раздел 6 →](../s06_input_size/THEORY.md)

**Простыми словами.** Кроме времени интервьюер почти всегда спрашивает: «А по памяти?» Это
вопрос о том, **сколько дополнительных данных создаёт решение** в зависимости от n. Входные
данные не считаются — они уже были до вызова функции. Считаем то, что функция **завела сама**:
новые списки, множества, словари, копии, глубину рекурсии.

```python
def total(prices):
    result = 0                   # одна переменная — сколько бы ни было цен
    for p in prices:
        result += p
    return result
# память O(1): пара переменных, их число не растёт с n

def doubled(prices):
    return [p * 2 for p in prices]   # новый список из n элементов
# память O(n)

def has_duplicate(items):
    seen = set()                 # в худшем случае все n элементов окажутся в seen
    for x in items:
        if x in seen:
            return True
        seen.add(x)
    return False
# время O(n), память O(n)
```

---

### Что занимает память

- **Новые коллекции:** `set(...)`, `Counter(...)`, `dict`, comprehension, `sorted(...)` — O(размер).
- **Копии и срезы:** `lst[:]`, `lst[1:]`, `copy.deepcopy`, `s.upper()` — O(размер копии).
- **Стек рекурсии:** каждый незавершённый вызов хранит свои переменные. Рекурсия глубины n —
  **O(n) памяти**, даже если внутри нет никаких списков. В Python глубина ограничена
  (`sys.getrecursionlimit()`, по умолчанию 1000) — на больших входах рекурсия падает с
  `RecursionError`.
- **Не занимают** (O(1)): счётчики, индексы, указатели `left`/`right`, генераторы, которые
  отдают по одному элементу.

```
 рекурсия total(nums, i):   total(…, 0)
                             └ total(…, 1)
                                └ total(…, 2)       ← n кадров одновременно в стеке
                                   └ …                 → O(n) памяти
```

### Обмен: память ↔ время

Самый частый приём оптимизации — **потратить O(n) памяти, чтобы сэкономить время**:
множество `seen` превращает O(n²) в O(n). Это почти всегда хорошая сделка, и её стоит
**проговорить вслух**: «Заведу set — это O(n) памяти, зато поиск станет O(1), и итог — O(n)
по времени вместо O(n²)».

Обратная ситуация — когда просят **O(1) памяти** («in place», «без дополнительной памяти»).
Тогда set нельзя, и выручают другие приёмы: сортировка на месте, два указателя (A3),
перезапись в тот же массив.

```python
def move_zeros(nums):            # на месте: O(n) времени, O(1) памяти
    write = 0
    for x in nums:
        if x != 0:
            nums[write] = x
            write += 1
    for i in range(write, len(nums)):
        nums[i] = 0
```

### Генератор против списка

```python
squares = [x * x for x in range(10**6)]   # список: миллион объектов в памяти — O(n)
total = sum(x * x for x in range(10**6))  # генератор: по одному числу за раз — O(1)
```

Если результат нужен один раз и по порядку — генератор экономит память. Подробно — в C5.

---

**Частая ошибка.** Забыть про стек рекурсии и сказать «памяти O(1), я же ничего не создаю».
Рекурсия глубины n — это O(n) памяти. Вторая ошибка — забыть, что `sorted(lst)` создаёт **новый**
список (O(n) памяти), а `lst.sort()` сортирует на месте.

<details><summary>Проверь себя: сколько памяти?</summary>

1. `max(nums)` — O(1): одна переменная с текущим максимумом.
2. `sorted(nums)[-1]` — O(n): создаётся отсортированная копия.
3. `Counter(words).most_common(1)` — O(k), где k — число **разных** слов; в худшем случае все разные → O(n).
4. Рекурсивный обход дерева глубины h — O(h) на стек.
</details>
