# A0 · Раздел 2. Классы сложности: от O(1) до O(2ⁿ)

[← раздел 1](../s01_what_is_big_o/THEORY.md) · [оглавление урока](../README.md) · [раздел 3 →](../s03_python_ops/THEORY.md)

**Простыми словами.** На практике встречается всего шесть-семь «форм роста». Их надо узнавать
в коде с первого взгляда и помнить, насколько они различаются на больших данных.

| Сложность | Название | n = 10 | n = 1 000 | n = 1 000 000 | Где встречается |
|---|---|---|---|---|---|
| O(1) | константа | 1 | 1 | 1 | `d[key]`, `lst[i]`, `append` |
| O(log n) | логарифм | 3 | 10 | 20 | бинарный поиск |
| O(n) | линейная | 10 | 1 000 | 1 000 000 | один проход по данным |
| O(n log n) | «эн лог эн» | 33 | 10 000 | 20 000 000 | `sorted()` |
| O(n²) | квадратичная | 100 | 1 000 000 | 10¹² | вложенный цикл по тем же данным |
| O(2ⁿ) | экспонента | 1 024 | ≈10³⁰¹ | — | перебор всех подмножеств |

Python делает примерно **10⁷ простых операций в секунду**. Значит, на миллионе элементов
O(n) — доли секунды, O(n log n) — пара секунд, а O(n²) — 10¹² операций, то есть **дни**.
Вот почему на собесе так важно не написать квадрат там, где можно линию.

---

### O(1) — константа

Время **не зависит** от размера данных. Сколько бы ни было элементов, действие одно.

```python
user = users_by_id[42]   # dict: сразу идём в нужную ячейку по хешу
first = items[0]         # list: адрес элемента вычисляется по индексу
items.append(5)          # добавить в конец
n = len(items)           # длина хранится в объекте, её не пересчитывают
```

O(1) не значит «одна операция» — значит «фиксированное число операций». Функция из 50 строк
без циклов по данным — тоже O(1).

### O(log n) — логарифм

Каждый шаг **делит задачу пополам** (или на любую долю). Сколько раз можно разделить n пополам,
пока не останется 1? Ровно log₂ n раз.

```python
def binary_search(sorted_nums, target):
    lo, hi = 0, len(sorted_nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2           # смотрим в середину
        if sorted_nums[mid] == target:
            return mid
        if sorted_nums[mid] < target:
            lo = mid + 1               # отбросили левую половину
        else:
            hi = mid - 1               # отбросили правую половину
    return -1
```

```
 1 000 000 → 500 000 → 250 000 → … → 2 → 1      ≈ 20 шагов
```

Как угадывать игрой «больше-меньше» число от 1 до миллиона: 20 вопросов хватит всегда.
Логарифм растёт настолько медленно, что O(log n) на практике почти как O(1).

### O(n) — линейная

**Один проход** по данным (или несколько проходов подряд — константа отбрасывается).

```python
total = sum(prices)              # проход
biggest = max(prices)            # ещё проход — всё вместе O(n)
names = [u["name"] for u in users]
```

Для большинства задач на собесе O(n) — это **лучшее, что можно сделать**: хотя бы один раз
посмотреть на каждый элемент придётся.

### O(n log n) — «эн лог эн»

Сложность **хорошей сортировки**. `sorted()` и `list.sort()` в Python (алгоритм Timsort) —
O(n log n). Интуиция: log n «уровней» деления, на каждом уровне обрабатываются все n элементов.

```python
events.sort(key=lambda e: e["ts"])   # O(n log n)
```

Если решение начинается с сортировки, оно **не может быть быстрее** O(n log n). Иногда это
нормально, а иногда интервьюер ждёт O(n) через dict/set.

### O(n²) — квадратичная

**Вложенный цикл по тем же данным**: для каждого элемента просматриваем все (или все
оставшиеся).

```python
def has_duplicate(items):
    for i in range(len(items)):
        for j in range(i + 1, len(items)):
            if items[i] == items[j]:
                return True
    return False
```

Данных стало в 10 раз больше → работы в **100 раз** больше. На 10 000 элементов — 50 млн
сравнений, это уже секунды. Обычно это «решение в лоб» (brute force), с которого начинают и
которое потом улучшают.

### O(2ⁿ) — экспонента

Каждый элемент добавляет **удвоение** работы: «взять или не взять» для каждого из n элементов
даёт 2ⁿ вариантов. Типичный источник — **наивная рекурсия**, которая вызывает себя дважды:

```python
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)    # каждый вызов порождает два
```

```
                fib(5)
            ┌─────┴─────┐
         fib(4)       fib(3)        ← fib(3) считается заново, хотя уже был
        ┌──┴──┐       ┌──┴──┐
     fib(3) fib(2) fib(2) fib(1)    ← и fib(2) много раз
      …
```

fib(30) — 2,7 миллиона вызовов, fib(50) — не дождёшься. Лечится **кэшем** (`@functools.cache`):
каждое значение считается один раз, и сложность падает до O(n). Подробно — в A9 и A14.

---

**Частая ошибка.** Путать O(log n) и O(n). Признак логарифма — **на каждом шаге отбрасывается
доля данных** (половина), а не один элемент. Цикл `while n > 0: n -= 1` — это O(n), а
`while n > 0: n //= 2` — O(log n).

<details><summary>Проверь себя: какая сложность у каждой строки?</summary>

1. `nums[len(nums) // 2]` — O(1): индекс и длина.
2. `sorted(nums)[0]` — O(n log n): сначала сортировка всего списка. Для минимума есть `min(nums)` за O(n).
3. `while x > 1: x //= 3` — O(log n): делим на 3, основание логарифма не важно.
4. `[a + b for a in nums for b in nums]` — O(n²): два `for` в одном comprehension — это вложенный цикл.
</details>
