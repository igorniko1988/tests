**Простыми словами.** На лайвкодинге оценивают не только «работает ли код», а **как ты
думаешь**. Молча написанное правильное решение получает меньше баллов, чем решение, к которому
ты пришёл вслух и по шагам. Поэтому у каждой задачи один и тот же порядок из шести шагов —
выучи его и используй во всём треке A.

```
 1. Уточнить  →  2. Примеры  →  3. В лоб + сложность  →  4. Улучшить  →  5. Код  →  6. Проверить
    (1–2 мин)     (1–2 мин)       (2 мин, вслух)          (3–5 мин)     (10 мин)    (3–5 мин)
```

---

### Шаг 1. Уточнить условие

Задай 2–4 вопроса, прежде чем писать. Это не трата времени, а **часть оценки**.

- **Какой вход:** может ли быть пустым? Есть ли отрицательные числа, дубли, `None`?
  Отсортирован ли? Регистр букв важен?
- **Какой выход:** индекс или значение? Что вернуть, если ответа нет (`-1`, `None`, исключение)?
  Если ответов несколько — любой или первый?
- **Размер данных** (раздел 6): «Сколько элементов может быть?»
- **Можно ли менять вход** на месте?

### Шаг 2. Разобрать примеры руками

Возьми пример из условия и **проговори ответ** без кода. Потом придумай 2–3 своих —
особенно **краевые случаи**: пустой вход, один элемент, все одинаковые, ответа нет.
Эти же примеры потом станут твоими тестами на шаге 6.

### Шаг 3. Решение в лоб и его сложность

Назови самое простое решение, которое точно работает, и **оцени его**:
«Можно перебрать все пары — это O(n²) по времени и O(1) по памяти». Код писать не обязательно —
достаточно сказать. Если n маленький (раздел 6), иногда этого и хватает.

### Шаг 4. Улучшить

Ищи, **что в решении в лоб делается повторно**. Вопросы-подсказки:

- Я много раз ищу что-то в списке? → **set/dict**, поиск за O(1) (A2).
- Данные отсортированы или их можно отсортировать? → **два указателя**, бинарный поиск (A3, A7).
- Нужен подотрезок подряд? → **скользящее окно**, префиксные суммы (A4, A8).
- Нужно «ближайшее большее», скобки? → **стек** (A5).

Скажи новую сложность вслух до того, как пишешь код: «С dict будет один проход — O(n) времени,
O(n) памяти».

### Шаг 5. Код

- Понятные имена: `seen`, `counts`, `left`/`right`, а не `a`, `b`, `tmp2`.
- Сначала основной случай, краевые — проверками в начале (`if not nums: return -1`).
- Комментируй **вслух**, что делаешь: «тут кладу число в словарь после проверки, чтобы не
  найти пару с самим собой».

### Шаг 6. Проверить

**Пройди код руками** на примере из шага 2: строка за строкой, со значениями переменных. Потом
краевые случаи. Найденный самим баг — плюс, а не минус. В конце ещё раз назови итоговую сложность.

### Пример целиком: two sum

*Условие:* дан список чисел и `target`. Вернуть индексы двух чисел, сумма которых равна `target`.

1. **Уточняю:** «Ответ всегда есть? Можно взять одно число дважды? Если пар несколько — любую?»
   Пусть: может не быть → `None`; одно число дважды нельзя; любую.
2. **Примеры:** `[2, 7, 11, 15]`, target 9 → `(0, 1)`. `[3, 3]`, 6 → `(0, 1)`. `[1]`, 2 → `None`.
3. **В лоб:** все пары `i < j` — O(n²) время, O(1) память.
4. **Улучшаю:** для каждого числа я ищу «пару» `target - x` среди уже просмотренных — это
   повторяющийся поиск. Положу просмотренные в dict `{число: индекс}` — поиск за O(1).
   Итог O(n) время, O(n) память.
5. **Код:**

```python
def two_sum(nums, target):
    seen = {}                          # число → индекс, где оно встретилось
    for j, x in enumerate(nums):
        need = target - x              # какое число нужно в пару к x
        if need in seen:               # O(1): поиск по ключу dict
            return seen[need], j
        seen[x] = j                    # кладём ПОСЛЕ проверки — иначе [3], 6 найдёт пару с самим собой
    return None
```

6. **Проверяю** `[3, 3]`, 6: j=0, x=3, need=3, `seen` пуст → кладём `{3: 0}`. j=1, x=3, need=3,
   есть в `seen` → `(0, 1)`. ✓ `[1]`, 2: need=1, `seen` пуст, кладём, цикл кончился → `None`. ✓

---

**Частая ошибка.** Сразу начинать писать код. Через 10 минут выясняется, что задача понята не
так, а времени уже нет. Вторая — молчать: интервьюер не может оценить мысли, которых не слышит.
