# A0 · Раздел 1. Что такое Big-O и как его считать

[← оглавление урока](../README.md) · [раздел 2 →](../s02_growth_classes/THEORY.md)

**Простыми словами.** Big-O (читается «О большое») — это ответ на вопрос: *во сколько раз
медленнее станет программа, если данных станет больше?* Не «сколько секунд она работает» —
секунды зависят от компьютера, версии Python и погоды, — а **как растёт работа вместе с
размером входа**.

Размер входа обозначают буквой **n**: длина списка, число символов в строке, количество
пользователей в ответе API. Дальше считаем **шаги** — простые действия вроде сравнения, сложения,
обращения по индексу — и смотрим, как их число зависит от n.

```python
def total(prices):          # prices — список из n чисел
    result = 0              # 1 шаг
    for p in prices:        # цикл повторится n раз
        result += p         #   по 1 шагу на каждый проход → n шагов
    return result           # 1 шаг
# всего: n + 2 шага
```

Список из 10 цен — 12 шагов, из 1000 — 1002, из миллиона — 1 000 002. Работа растёт **прямо
пропорционально** n. Такую сложность записывают **O(n)** — «линейная».

---

### Три правила упрощения

Точная формула (`n + 2`, `3n² + 5n + 7`) никому не нужна. Big-O описывает только **форму роста**
при больших n, поэтому формулу упрощают.

**Правило 1. Константы-множители отбрасываем.** `2n`, `3n`, `n/2` → всё это **O(n)**.

Почему так можно: если данных стало в 10 раз больше, то и `n`, и `3n` выросли ровно в 10 раз.
Множитель 3 говорит «эта программа в 3 раза медленнее той», но не меняет *характер* роста.
Такие отличия зависят от железа и мелочей реализации, а Big-O специально их не видит.

```python
for x in items:      # n шагов
    ...
for x in items:      # ещё n шагов
    ...
# 2n → O(n). Два цикла ПОДРЯД — это не O(n²)!
```

**Правило 2. Младшие слагаемые отбрасываем.** `n² + n` → **O(n²)**, `n + 100` → **O(n)**.

При n = 1000: n² = 1 000 000, а n = 1000 — это 0,1% от суммы. Чем больше n, тем меньше
младший член влияет. Оставляем только самый быстрорастущий.

**Правило 3. По умолчанию — худший случай.** Если поиск *может* закончиться на первом элементе,
а *может* пройти весь список, говорят O(n). Интервьюер спрашивает именно про худший случай,
если не уточнил иное. Лучший случай («нашли сразу») — не оценка, а везение.

```python
def find(items, target):
    for i, x in enumerate(items):
        if x == target:
            return i         # повезло — вышли рано
    return -1                # худший случай: прошли все n элементов → O(n)
```

### Вложенные циклы: умножаем

Цикл **внутри** цикла: на каждый шаг внешнего цикла внутренний делает свои шаги целиком.
Шаги **перемножаются**.

```python
for a in items:          # n раз
    for b in items:      #   × n раз
        compare(a, b)    # n · n = n² → O(n²)
```

```
 a=1: b=1 b=2 b=3 … b=n      ← n шагов
 a=2: b=1 b=2 b=3 … b=n      ← n шагов
 …
 a=n: b=1 b=2 b=3 … b=n      ← n шагов
                               всего n строк по n = n²
```

**Частый вариант — «каждая пара один раз»:** `for j in range(i + 1, n)`. Шагов n(n−1)/2, то есть
примерно n²/2. По правилу 1 делим-на-2 отбрасываем → всё равно **O(n²)**.

**Вложенность ≠ автоматически n².** Если внутренний цикл не зависит от n, он — константа:

```python
for x in items:              # n раз
    for d in range(3):       #   × 3 — всегда 3, сколько бы ни было items
        ...
# 3n → O(n)
```

### Разные входы — разные буквы

Если у функции два независимых входа (два списка разной длины), их размеры обозначают разными
буквами — обычно **n** и **m**:

```python
def common(a, b):            # len(a) = n, len(b) = m
    for x in a:              # n раз
        for y in b:          #   × m раз
            ...
# O(n · m), а НЕ O(n²): если a из 10 элементов, а b из миллиона — это очень разные вещи
```

Подряд идущие циклы по разным входам — **O(n + m)**.

---

**Частая ошибка.** Видеть два цикла и говорить O(n²). Сначала посмотри: циклы **вложены** или
идут **подряд**? И от чего зависит длина внутреннего цикла — от n или от константы?

<details><summary>Проверь себя: какая сложность?</summary>

```python
def f(nums):
    total = sum(nums)            # (1)
    for x in nums:               # (2)
        for k in range(10):      # (3)
            total += x * k
    return total
```

`sum(nums)` — это скрытый цикл на n шагов. Дальше n × 10 шагов. Итого n + 10n = 11n → **O(n)**.
</details>
