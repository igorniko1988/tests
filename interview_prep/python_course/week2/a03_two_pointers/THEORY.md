# A3 · Два указателя

**Смысл темы.** Вместо вложенного цикла «каждый с каждым» (O(n²)) заводим два индекса и
двигаем их по массиву по правилу: каждый шаг сдвигает один из них, и ни один не возвращается
назад. Всего шагов не больше n — получается O(n) по времени и O(1) по памяти. Паттерн работает,
когда у данных есть **порядок**: массив отсортирован или важна симметрия (палиндром).

**Сигналы в условии:** «отсортированный массив», «пара/тройка с суммой», «на месте, без доп.
памяти», «палиндром», «убрать дубли/нули, сохранив порядок», «слить два отсортированных».

---

### 1. Вариант «с двух концов»

`left` стартует с начала, `right` — с конца, идут навстречу, пока не встретятся.

```python
def two_sum_sorted(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:
        s = nums[left] + nums[right]
        if s == target:
            return [left, right]
        if s < target:
            left += 1          # сумма мала — берём число побольше
        else:
            right -= 1         # сумма велика — берём число поменьше
    return []
```

```
nums = [1, 3, 4, 6, 9], target = 10

 L           R     1 + 9 = 10  ✓ → [0, 4]

target = 7:
 L           R     1 + 9 = 10 > 7  → R влево
 L        R        1 + 6 = 7   ✓ → [0, 3]
```

- **Почему можно отбросить элемент:** если `nums[left] + nums[right] > target`, то `nums[right]`
  с ЛЮБЫМ элементом правее `left` даст ещё больше — он точно не в ответе, его можно выкинуть.
  Каждый шаг выкидывает один элемент → не больше n шагов.
- **Условие цикла `left < right`:** указатели не должны совпасть — элемент нельзя брать дважды.
- **Работает только на отсортированном.** Для неотсортированного two sum — dict (A2), O(n).

### 2. Вариант «чтение и запись» (быстрый и медленный)

Оба указателя идут слева направо: `read` смотрит каждый элемент, `write` показывает, куда
положить следующий «хороший». Так меняют массив **на месте**.

```python
def remove_duplicates(nums):          # nums отсортирован
    if not nums:
        return 0
    write = 1                          # nums[0] всегда остаётся
    for read in range(1, len(nums)):
        if nums[read] != nums[write - 1]:   # новое значение
            nums[write] = nums[read]
            write += 1
    return write                       # длина «хорошей» части
```

```
[1, 1, 2, 2, 3]
 w=1, r=1: 1 == 1 → пропуск
 r=2: 2 != 1 → nums[1] = 2, w=2   [1, 2, 2, 2, 3]
 r=3: 2 == 2 → пропуск
 r=4: 3 != 2 → nums[2] = 3, w=3   [1, 2, 3, 2, 3]
 ответ 3, первые три элемента — [1, 2, 3]
```

- **Инвариант:** всё левее `write` — уже готовый ответ. Это то, что нужно проговорить на собесе.
- **Тот же приём:** move zeros (A1 t02), «удалить все вхождения» (C3 t01), отфильтровать на месте.

### 3. Два указателя по двум массивам

Слияние двух отсортированных (A1 t03): `i` идёт по первому, `j` по второму, каждый шаг берём
меньший и сдвигаем его указатель. Тот же приём — «пересечение двух отсортированных»,
«является ли подпоследовательностью» (A1 t09).

```python
def intersect_sorted(a, b):
    i = j = 0
    result = []
    while i < len(a) and j < len(b):
        if a[i] == b[j]:
            result.append(a[i]); i += 1; j += 1
        elif a[i] < b[j]:
            i += 1
        else:
            j += 1
    return result
```

### 4. Шаблон рассуждения на собесе

1. **Решение в лоб:** два цикла, O(n²). Сказать вслух.
2. **Что даёт порядок?** «Массив отсортирован → если сумма велика, правый можно отбросить».
3. **Какие указатели и куда смотрят?** Нарисовать на примере из 5 элементов.
4. **Правило сдвига** и почему не теряем ответ.
5. **Условие остановки:** `left < right` или `read < len(nums)`.
6. **Крайние случаи:** пустой, один элемент, все одинаковые, ответа нет.
7. **Сложность:** O(n) время, O(1) память (+ O(n log n), если сначала сортируем).

### 5. 3sum: сортировка + два указателя

```python
def three_sum(nums):
    nums = sorted(nums)
    result = []
    for i in range(len(nums) - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue                            # тот же первый элемент — дубль
        left, right = i + 1, len(nums) - 1
        while left < right:
            s = nums[i] + nums[left] + nums[right]
            if s < 0:
                left += 1
            elif s > 0:
                right -= 1
            else:
                result.append([nums[i], nums[left], nums[right]])
                left += 1
                while left < right and nums[left] == nums[left - 1]:
                    left += 1                   # пропустить одинаковые
    return result
```

- **Сложность:** сортировка O(n log n) + для каждого `i` проход O(n) → O(n²). Лучше для 3sum нет.
- **Дубли — главная сложность задачи:** пропускаем одинаковые `nums[i]` и одинаковые `nums[left]`.

---

**Частые ошибки.**
- Применить «с двух концов» к НЕотсортированному массиву.
- `while left <= right` там, где элемент нельзя брать дважды.
- Забыть сдвинуть указатель в какой-то ветке — бесконечный цикл.
- В 3sum вернуть дубли троек или потерять ответы, пропуская одинаковые не там.
- «На месте» создать новый список: `nums = [...]` вместо изменения `nums[i]` / `nums[:]`.

### Собес

- **Когда применять два указателя?** Когда у данных есть порядок: отсортированный массив
  (пара/тройка с суммой, слияние), симметрия (палиндром) или нужно отфильтровать на месте. Паттерн
  превращает O(n²) в O(n) по времени при O(1) памяти.
- **Почему в two sum II можно сдвигать указатели и не потерять ответ?** Массив отсортирован: если
  сумма больше цели, правый элемент с любым оставшимся левым даст ещё больше — он не входит в
  ответ, его отбрасываем. Каждый шаг отбрасывает один элемент, всего n шагов.
- **Two sum: dict или два указателя?** Неотсортированный — dict, O(n) время и O(n) память.
  Отсортированный — два указателя, O(n) и O(1). Сортировать ради указателей — O(n log n) и теряются
  исходные индексы.
- **Как убрать дубли на месте?** Указатели чтения и записи: всё левее `write` — ответ;
  новый элемент копируем в `nums[write]` и сдвигаем `write`. O(n), O(1).
