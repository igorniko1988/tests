# C3 · Раздел 6. deque — очередь с двух концов

[← раздел 5](../s05_counter_defaultdict/THEORY.md) · [оглавление урока](../README.md) · [раздел 7 →](../s07_sorting/THEORY.md)

**Простыми словами.** `deque` (читается «дек», double-ended queue) — очередь, в которую можно
добавлять и из которой можно забирать **с обоих концов за O(1)**. У списка быстрый только правый
конец: `pop(0)` сдвигает все элементы — O(n) (раздел 1). Нужна очередь «пришёл — ушёл» — бери
deque.

```python
from collections import deque

q = deque([1, 2, 3])
q.append(4)        # справа    → deque([1, 2, 3, 4])
q.appendleft(0)    # слева     → deque([0, 1, 2, 3, 4])
q.pop()            # 4, справа
q.popleft()        # 0, слева  — O(1), в отличие от list.pop(0)
```

---

### 1. Почему с обоих концов быстро

Список — один сплошной блок, у которого «начало» прибито к первой ячейке. deque устроен как
**цепочка блоков** по 64 ссылки. Добавить слева — положить в свободную ячейку левого блока или
прицепить новый блок слева. Ничего не сдвигается.

```
list:   [ a | b | c | d | e ]          pop(0) → сдвинуть b, c, d, e влево: O(n)

deque:  ┌───────────┐   ┌───────────┐
        │ · · · a b │ ⇄ │ c d e · · │    popleft → взять a, сдвинуть указатель начала: O(1)
        └───────────┘   └───────────┘    appendleft → положить в · слева от a: O(1)
```

Цена — доступ по индексу в **середину** медленнее: `q[i]` идёт по блокам, это O(n) в худшем
случае. `q[0]` и `q[-1]` — O(1).

| Операция | list | deque |
|---|---|---|
| добавить / забрать справа | O(1) | O(1) |
| добавить / забрать слева | **O(n)** | **O(1)** |
| `x[i]` в середине | O(1) | O(n) |
| срез `x[1:3]` | есть | нет — TypeError |

### 2. maxlen — «последние N»

`deque(maxlen=N)` хранит не больше N элементов. Добавил лишний — элемент **с другого конца**
выпадает сам:

```python
last = deque(maxlen=3)
for event in ["e1", "e2", "e3", "e4", "e5"]:
    last.append(event)
print(last)       # deque(['e3', 'e4', 'e5'], maxlen=3)
```

```
append(e1)  [e1]
append(e2)  [e1, e2]
append(e3)  [e1, e2, e3]         заполнено
append(e4)  [e2, e3, e4]         e1 выпал слева
append(e5)  [e3, e4, e5]         e2 выпал слева
```

С `appendleft` выпадает **правый** элемент. Память — O(N), сколько бы событий ни пришло. Так
делают «последние 100 строк лога для отчёта», `tail -n`, скользящее окно метрик. Задача t06.

### 3. Полезные методы

```python
q = deque([1, 2, 3, 4])
q.rotate(1)          # deque([4, 1, 2, 3]) — сдвиг по кругу вправо
q.rotate(-1)         # обратно
q.extend([5, 6])     # справа по одному
q.extendleft([7, 8]) # слева по одному: сначала 7, потом 8 перед ним → deque([8, 7, ...])
len(q), q[0], q[-1]
```

`extendleft` переворачивает порядок: каждый элемент встаёт в начало по очереди.

`deque("abc")` — это `deque(['a', 'b', 'c'])`: конструктор принимает iterable, строка
раскладывается на символы. Одна строка-элемент — `deque(["abc"])`.

### 4. Где это используют

- **BFS** — обход в ширину графа или дерева: `queue.popleft()`, соседей в `queue.append(...)`
  (трек A, A8).
- **Скользящее окно** — максимум за последние k элементов (A5).
- **Последние N** событий, запросов, строк лога — `maxlen`.
- **Очередь задач** в одном потоке. Для очереди между потоками — `queue.Queue` (C12).

---

**Частая ошибка.** Очередь на списке: `while queue: node = queue.pop(0)`. На 10 узлах не заметно,
на 100 000 — O(n²), и решение «не проходит по времени». На лайвкодинге интервьюер обязательно
спросит, почему не deque.

<details><summary>Проверь себя: что выведет?</summary>

```python
from collections import deque
q = deque([1, 2, 3], maxlen=3)
q.appendleft(0)
q.append(9)
print(list(q))
```
`[1, 2, 9]`. `appendleft(0)` при полном деке выкидывает элемент с **противоположного** конца —
правый `3` → `[0, 1, 2]`. `append(9)` выкидывает левый — `0` → `[1, 2, 9]`.
</details>
