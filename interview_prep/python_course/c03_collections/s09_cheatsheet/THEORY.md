# C3 · Раздел 9. Шпаргалка и собес

[← раздел 8](../s08_autotests/THEORY.md) · [оглавление урока](../README.md)

## Шпаргалка

1. `list` — массив ссылок подряд. `a[i]`, `append`, `pop()` — O(1); `insert(0)`, `pop(0)`, `in`, `remove` — O(n).
2. `append` — амортизированное O(1): память выделяется с запасом, иногда весь список копируется.
3. Меняющие методы (`sort`, `append`, `reverse`…) возвращают `None`. `sorted()` возвращает новый список.
4. Не удаляй из списка, по которому идёшь циклом: пропустишь элементы. Фильтруй comprehension'ом.
5. Кортеж делает запятая: `(1)` — int, `(1,)` — tuple, `x = 1,` — tuple.
6. Кортеж хешируем, только если всё внутри хешируемо. Неизменяемы ссылки, а не объекты по ним.
7. Распаковка: количество должно совпасть; `*rest` всегда список.
8. `dict` — хеш-таблица: `hash(key) % размер` → ячейка. Поиск, вставка, удаление — O(1) в среднем.
9. Ключи хешируемые; `1`, `1.0`, `True` — один ключ.
10. dict помнит порядок вставки (3.7+); `==` порядок не учитывает.
11. Менять размер dict/set при переборе нельзя — RuntimeError. Перебирай `list(d)`.
12. `set` — хеш-таблица без значений: уникальность, `in` за O(1), порядка нет. Пустое — `set()`.
13. `|` `&` `-` `^`, `<=` — подмножество. Множество прячет дубли.
14. `Counter` — частоты, `most_common` (ничьи — порядок появления), сравнение без учёта порядка с дублями.
15. `defaultdict(фабрика)` — фабрику без скобок; чтение `d[k]` создаёт ключ; наружу — `dict(d)`.
16. `deque` — O(1) с обоих концов, `maxlen` выкидывает с противоположного конца; середина — O(n).
17. Сортировка стабильна; несколько полей — ключ-кортеж или несколько проходов с конца.
18. Строки-числа сортируй с `key=int` / `key=Decimal`; None — ключом `(x is None, x)`.

## Собес

- **list против tuple: в чём разница?**
  Список изменяемый: можно добавлять, удалять, заменять элементы. Кортеж после создания не
  меняется. Отсюда отличия: кортеж хешируемый (если всё внутри хешируемо) и может быть ключом
  словаря, занимает меньше памяти (нет запаса под рост). По смыслу список — коллекция однотипных
  элементов переменной длины, кортеж — запись с фиксированными полями, как `(symbol, price)`.
  Важно: неизменяемы ссылки внутри кортежа, а объект по ссылке, например список, менять можно.

- **Как устроен list? Почему `append` быстрый, а `insert(0)` медленный?**
  Это динамический массив: ссылки на объекты лежат в памяти подряд. Доступ по индексу — одна
  формула, O(1). Память выделяется с запасом, поэтому `append` обычно просто кладёт ссылку в
  свободную ячейку; когда запас кончается, список копируется в блок побольше — в среднем выходит
  O(1). `insert(0)` и `pop(0)` сдвигают все элементы — O(n). Для очереди используют deque.

- **Как устроен dict и почему поиск O(1)?**
  Это хеш-таблица. От ключа считается `hash`, из него — номер ячейки, и Python сразу идёт в эту
  ячейку и сравнивает ключ через `==`. Перебора нет, поэтому в среднем O(1). Если разные ключи
  попали в одну ячейку — коллизия, CPython ищет следующую ячейку (открытая адресация). Когда
  таблица заполнена примерно на 2/3, она увеличивается и ключи перекладываются. В худшем случае,
  когда хеши совпадают у всех ключей, — O(n). Поэтому ключ должен быть хешируемым и хеш не должен
  меняться.

- **Почему dict сохраняет порядок?**
  С Python 3.7 это гарантия языка. Пары хранятся в отдельном массиве в порядке добавления, а сама
  хеш-таблица хранит только номера записей в этом массиве. Перебор идёт по массиву записей. Это
  ещё и экономит память. Перезапись значения позицию не меняет, удаление и повторное добавление
  ставит ключ в конец.

- **Чем set отличается от list? Когда что?**
  set — хеш-таблица без значений: элементы уникальны, `in` за O(1), порядка нет, элементы должны
  быть хешируемыми. list — порядок и дубли, `in` за O(n). Если нужно много раз проверять
  «есть ли элемент» — set. Если важны порядок или дубли — list. В тестах помню, что `set` прячет
  дубли, и для сравнения без порядка беру `Counter` или `sorted`.

- **Зачем deque, если есть list?**
  У списка быстрый только правый конец, `pop(0)` — O(n). deque — цепочка блоков, добавление и
  удаление с обоих концов O(1). Поэтому очереди (BFS) и «последние N» через `maxlen` делают на
  deque. Минус — доступ к середине O(n) и нет срезов.

- **Что такое стабильная сортировка и зачем она?**
  Элементы с равным ключом сохраняют исходный порядок. Это позволяет сортировать по нескольким
  полям в несколько проходов: сначала по второстепенному, потом по главному. Сортировка Python
  (Timsort) стабильна, O(n log n), на почти упорядоченных данных близка к O(n).

- **Когда defaultdict удобнее обычного dict?**
  Когда нужно группировать или считать: `groups[key].append(x)` без проверки, есть ли ключ.
  Фабрика вызывается заново для каждого нового ключа, поэтому у каждого свой список. Подвох —
  даже чтение `d[k]` создаёт ключ, поэтому проверку делаю через `in` или `get`, а наружу отдаю
  `dict(d)`.

- **Как сравнить два списка без учёта порядка?**
  `sorted(a) == sorted(b)` или `Counter(a) == Counter(b)` — оба учитывают дубли. `set(a) == set(b)`
  дубли теряет, годится только когда дубли невозможны или не важны. Для списка словарей —
  `sorted` с `key` по id.

- **Можно ли менять словарь во время перебора?**
  Значения — можно. Добавлять или удалять ключи — нет, будет `RuntimeError: dictionary changed
  size during iteration`. Перебираю копию ключей `list(d)` или собираю новый словарь
  comprehension'ом.
