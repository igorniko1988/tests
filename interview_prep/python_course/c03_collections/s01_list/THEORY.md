# C3 · Раздел 1. list — динамический массив

[оглавление урока](../README.md) · [раздел 2 →](../s02_tuple/THEORY.md)

**Простыми словами.** Список — это ряд ячеек в памяти, которые стоят **подряд**. В каждой ячейке
лежит не сам объект, а **ссылка** на него (C1: имена и ссылки). Поэтому в одном списке могут жить
объекты любых типов, а «достать элемент номер i» — это просто «отступить от начала на i ячеек».

```python
users = ["ann", 42, None]

#  users ──► ┌──────┬──────┬──────┐
#            │  ●   │  ●   │  ●   │      ячейки 0, 1, 2 стоят подряд
#            └──┼───┴──┼───┴──┼───┘
#               ▼      ▼      ▼
#            'ann'    42     None       сами объекты лежат где угодно
```

«Динамический» значит, что размер растёт сам: `append` добавляет в конец, Python при нужде
выделяет память побольше.

---

### 1. Почему `a[i]` и `append` быстрые — O(1)

**Доступ по индексу.** Адрес ячейки считается одной формулой: `начало + i × размер_ссылки`.
Неважно, 10 элементов в списке или 10 миллионов, — одна арифметическая операция.

**append — с запасом.** Python выделяет ячеек **больше**, чем нужно сейчас. Пока запас есть,
`append` просто кладёт ссылку в следующую свободную ячейку:

```python
import sys

a = []
for i in range(10):
    print(len(a), sys.getsizeof(a))
    a.append(i)
# 0 56     ← пустой список, ячеек нет
# 1 88     ← выделено сразу 4 ячейки (88 − 56 = 32 байта = 4 × 8)
# 2 88
# 3 88
# 4 88
# 5 120    ← запас кончился: выделено 8 ячеек
# ...
# 9 184    ← дальше 16
```

```
ёмкость 4:  [ a | b | c | d ]                 append(e) — места нет
            ▼ выделить новый блок побольше, скопировать 4 ссылки
ёмкость 8:  [ a | b | c | d | e | · | · | · ]  следующие 3 append — бесплатно
```

Копирование при росте — O(n), но случается редко, и каждый раз запас растёт пропорционально
размеру. Если разделить все затраты на все `append`, выйдет константа на один вызов. Это
называют **амортизированное O(1)** (A0, раздел 3).

### 2. Почему `insert(0, x)` и `pop(0)` медленные — O(n)

Ячейки стоят подряд, «дыр» быть не может. Вставка в начало сдвигает **все** элементы вправо,
удаление из начала — все влево:

```
insert(0, "z"):
  было:  [ a | b | c | d | · ]
          ↘   ↘   ↘   ↘            каждый элемент сдвигается на 1
  стало: [ z | a | b | c | d ]     n сдвигов → O(n)
```

То же с `del a[0]`, `a.remove(x)` (ищет и сдвигает хвост) и `x in a` (смотрит элементы по
одному). Нужна очередь «добавил в конец — забрал из начала» — бери `deque` (раздел 6).

| Операция | Сложность | Почему |
|---|---|---|
| `a[i]`, `a[i] = x`, `len(a)` | O(1) | адрес считается формулой, длина хранится |
| `a.append(x)`, `a.pop()` | O(1)* | работа с концом; * амортизированно |
| `a.insert(0, x)`, `a.pop(0)`, `del a[0]` | O(n) | сдвиг всех элементов |
| `x in a`, `a.index(x)`, `a.count(x)`, `a.remove(x)` | O(n) | перебор по одному |
| `a[i:j]` | O(j − i) | копирует ссылки среза в новый список |
| `a.extend(b)`, `a += b` | O(len(b)) | добавляет все элементы b |
| `a.sort()`, `sorted(a)` | O(n log n) | Timsort (раздел 7) |

### 3. Методы, которые меняют список, возвращают `None`

`append`, `extend`, `insert`, `remove`, `sort`, `reverse`, `clear` меняют **сам** список и
возвращают `None`. Это сделано специально: по `None` видно, что нового списка нет.

```python
nums = [3, 1, 2]
result = nums.sort()
print(result)       # None   — частая ошибка «отсортировал и потерял»
print(nums)         # [1, 2, 3]

nums = nums.append(4)   # ✗ теперь nums — None, список потерян
```

Новый список возвращают функции и операции **без** изменения исходного: `sorted(a)`, `a + b`,
`a[::-1]`, `list(reversed(a))`.

| Меняет на месте → `None` | Возвращает новый | Возвращает значение |
|---|---|---|
| `append`, `extend`, `insert`, `remove`, `sort`, `reverse`, `clear` | `sorted(a)`, `a + b`, `a[:]`, `a * 3` | `pop()` → элемент, `index(x)` → номер, `count(x)` → число |

### 4. Удаление: `remove`, `pop`, `del`

```python
a = ["x", "y", "x"]
a.remove("x")   # удаляет ПЕРВОЕ вхождение по значению → ['y', 'x']
a.pop()         # удаляет и возвращает ПОСЛЕДНИЙ → 'x', a == ['y']
a.pop(0)        # по индексу → 'y', a == []

[1, 2].remove(5)   # ValueError: list.remove(x): x not in list
[].pop()           # IndexError: pop from empty list
[1, 2].index(5)    # ValueError
```

`del a[i]` удаляет по индексу, `del a[1:3]` — кусок. `a.clear()` очищает список **на месте**:
все, у кого есть ссылка на этот список, увидят пустой.

### 5. Срезы: копия или изменение на месте

**Срез справа от `=`** создаёт **новый** список (поверхностная копия, C1 раздел 6):

```python
a = [1, 2, 3, 4]
b = a[1:3]       # [2, 3] — новый список
b.append(99)     # a не изменился
```

**Срез слева от `=`** заменяет кусок **в том же** списке. Длина может поменяться:

```python
a = [1, 2, 3, 4]
a[1:3] = ["x"]       # [1, 'x', 4]  — два элемента заменены одним
a[:] = [0, 0]        # [0, 0]       — объект тот же, заменено всё содержимое
```

`a[:] = ...` — способ заменить содержимое, **не создавая** новый объект. Пригодится в задаче t01.

```
a = [0, 0]        имя a переклеено на новый список; старый остался у тех, кто на него смотрит
a[:] = [0, 0]     тот же объект, внутри новые ссылки; все владельцы ссылки видят изменения
```

### 6. Нельзя удалять из списка, по которому идёшь циклом

`for` идёт по **индексам** 0, 1, 2… Если удалить текущий элемент, следующий сдвинется на его
место, а цикл перейдёт к индексу +1 и **перепрыгнет** его:

```python
nums = [1, 2, 2, 3]
for x in nums:
    if x == 2:
        nums.remove(x)
print(nums)    # [1, 2, 3]  — одна двойка осталась!
```

```
шаг i=1: x = 2      [1, 2, 2, 3]  → remove → [1, 2, 3]
                        ▲ вторая двойка сдвинулась на место индекса 1
шаг i=2: x = 3      [1, 2, 3]     индекс 1 уже пройден — двойку пропустили
```

**Как правильно:**

```python
nums = [x for x in nums if x != 2]       # новый список (обычно этого достаточно)
nums[:] = [x for x in nums if x != 2]    # то же, но в том же объекте — если на список ссылаются другие
for x in nums[:]:                        # идти по копии, удалять из оригинала (O(n²) из-за remove)
    ...
```

И не пиши `while x in nums: nums.remove(x)` — каждый `in` и `remove` проходит список, итого O(n²).

---

**Частая ошибка.** В тесте собрали список ожидаемых и «почистили» его в цикле через `remove`.
На двух одинаковых элементах подряд один остался, и тест сравнивает не то, что ты думаешь. Фильтруй
comprehension'ом, а не удалением на ходу.

<details><summary>Проверь себя: что выведет?</summary>

```python
a = [3, 1, 2]
b = a
a = sorted(a)
b.sort(reverse=True)
print(a, b)
```
`[1, 2, 3] [3, 2, 1]`. `sorted` создал новый список, и `a` переклеилось на него. `b` по-прежнему
смотрит на старый список, `b.sort(reverse=True)` отсортировал его на месте по убыванию.
</details>
