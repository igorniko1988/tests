# C3 · Раздел 7. Сортировка

[← раздел 6](../s06_deque/THEORY.md) · [оглавление урока](../README.md) · [раздел 8 →](../s08_autotests/THEORY.md)

**Простыми словами.** В Python два способа отсортировать:

- **`sorted(iterable)`** — принимает что угодно (список, кортеж, множество, ключи словаря,
  генератор) и возвращает **новый список**. Исходное не трогает.
- **`lst.sort()`** — есть только у списка, сортирует **на месте** и возвращает `None` (раздел 1).

У обоих одинаковые параметры: `key=` — по чему сортировать, `reverse=True` — по убыванию.
Внутри — алгоритм **Timsort**: O(n log n), а на почти отсортированных данных — почти O(n).

```python
prices = [30, 10, 20]
print(sorted(prices))                 # [10, 20, 30] — новый список
print(prices)                         # [30, 10, 20] — исходный не изменился
prices.sort(reverse=True)             # на месте → [30, 20, 10]
print(sorted({"b": 1, "a": 2}))       # ['a', 'b'] — перебор dict даёт ключи
print(sorted("cab"))                  # ['a', 'b', 'c'] — список символов, не строка
```

### 1. key — функция «по чему сравнивать»

`key` получает **один элемент** и возвращает значение, по которому его сравнивать. Python
вызывает `key` **один раз** на каждый элемент, запоминает результаты и сортирует по ним:

```python
words = ["banana", "apple", "Cherry"]
sorted(words)                    # ['Cherry', 'apple', 'banana'] — заглавные раньше строчных (код символа)
sorted(words, key=str.lower)     # ['apple', 'banana', 'Cherry'] — без учёта регистра
sorted(words, key=len)           # ['apple', 'banana', 'Cherry'] — по длине: 5, 6, 6

users = [{"name": "bob", "score": 7}, {"name": "ann", "score": 9}]
sorted(users, key=lambda u: u["score"])        # по очкам
```

```
элементы:   "banana"   "apple"   "Cherry"
key=len:       6          5         6        ← сортируются эти числа
результат:  "apple"(5)  "banana"(6)  "Cherry"(6)    banana и Cherry равны — порядок как был
```

Готовые функции вместо лямбд: `operator.itemgetter("score")` — то же, что
`lambda u: u["score"]`; `operator.attrgetter("price")` — `lambda o: o.price`.

### 2. Стабильность

Сортировка **стабильная**: элементы с одинаковым ключом остаются в том порядке, в каком были.

```python
orders = [("NEW", 1), ("FILLED", 2), ("NEW", 3), ("FILLED", 4)]
sorted(orders, key=lambda o: o[0])
# [('FILLED', 2), ('FILLED', 4), ('NEW', 1), ('NEW', 3)]
#   2 раньше 4 и 1 раньше 3 — как было в исходном списке
```

`reverse=True` стабильность **сохраняет**: равные элементы не переворачиваются.

### 3. Сортировка по нескольким полям

**Способ 1 — ключ-кортеж.** Кортежи сравниваются по очереди: первые элементы, при равенстве —
вторые и так далее.

```python
# по убыванию очков, при равенстве — по имени по алфавиту
sorted(users, key=lambda u: (-u["score"], u["name"]))
```

Минус работает только для **чисел** (и Decimal). Строку «по убыванию» минусом не развернёшь.

**Способ 2 — несколько проходов, начиная с последнего ключа.** Благодаря стабильности
второй проход не ломает порядок первого внутри равных групп:

```python
# по имени ПО УБЫВАНИЮ, при равенстве — по очкам по возрастанию
users.sort(key=lambda u: u["score"])               # 1) второстепенный ключ
users.sort(key=lambda u: u["name"], reverse=True)  # 2) главный ключ
```

```
после 1) по score:      (ann,5) (bob,5) (ann,9)
после 2) по name ↓:     (bob,5) (ann,5) (ann,9)    внутри «ann» порядок 5, 9 сохранён
```

### 4. Ловушки сравнения

```python
sorted(["10", "9", "100"])        # ['10', '100', '9'] — строки сравниваются посимвольно!
sorted(["10", "9", "100"], key=int)   # ['9', '10', '100']
sorted(amounts, key=Decimal)      # суммы из API приходят строками — сортируй по Decimal

sorted([3, None, 1])              # TypeError: '<' not supported between instances of 'NoneType' and 'int'
sorted([3, "a"])                  # TypeError — разные типы не сравниваются
sorted([3, None, 1], key=lambda x: (x is None, x))   # [1, 3, None] — None в конец
```

Как работает последний ключ: для чисел он `(False, 3)`, для None — `(True, None)`. `False < True`,
поэтому все None уходят в конец, а до сравнения самих `None` с числами дело не доходит.

### 5. min, max — тоже с key

```python
max(users, key=lambda u: u["score"])     # пользователь с максимумом, а не сам максимум
min([], default=None)                    # None вместо ValueError на пустом
max(d, key=d.get)                        # ключ словаря с наибольшим значением
```

`min`/`max` — O(n), сортировать ради одного максимума (`sorted(a)[-1]`, O(n log n)) не нужно.
Для топ-k из большого списка — `heapq.nlargest(k, items, key=...)`, O(n log k) (A9).

**Частая ошибка.** Проверка «API отдал ордера отсортированными по цене» как
`assert prices == sorted(prices)`, где `prices` — строки из JSON. Строки сортируются как текст,
и `"100.00"` окажется раньше `"9.50"`. Сравнивай с `sorted(prices, key=Decimal)`.

<details><summary>Проверь себя: что выведет?</summary>

```python
data = [("b", 2), ("a", 2), ("c", 1)]
print(sorted(data, key=lambda x: x[1]))
print(sorted(data, key=lambda x: -x[1])[0])
```
`[('c', 1), ('b', 2), ('a', 2)]` и `('b', 2)`. Ключ — только число; у `b` и `a` оно одинаковое,
и стабильная сортировка сохраняет их исходный порядок: `b` раньше `a`.
</details>
