# C3 · Раздел 3. dict — хеш-таблица

[← раздел 2](../s02_tuple/THEORY.md) · [оглавление урока](../README.md) · [раздел 4 →](../s04_set/THEORY.md)

**Простыми словами.** Словарь хранит пары «ключ → значение» и умеет найти значение по ключу
**сразу**, не перебирая все пары. Секрет — **хеш**: по ключу считается число `hash(key)`, а из
него — номер ячейки, где лежит пара. Поэтому `d[key]`, `d[key] = v`, `key in d` и `del d[key]`
работают в среднем за **O(1)** — сколько бы ключей ни было.

Сравни со списком пар: чтобы найти `"BTC"` в `[("ETH", 5), ("BTC", 100), ...]`, придётся
смотреть пары по одной — O(n). Словарь эту работу делает одной формулой.

---

### 1. Как устроена хеш-таблица

Таблица — массив **ячеек** (их ещё называют корзинами, buckets). Чтобы положить пару:

```
1) h = hash(key)              hash("BTC")  → например 7203411960338273921
2) i = h % размер_таблицы     7203411960338273921 % 8 → 1
3) пара кладётся в ячейку i

   ячейка:   0      1             2      3      4             5      6      7
           ┌─────┬─────────────┬─────┬─────┬─────────────┬─────┬─────┬─────┐
           │     │ "BTC" → 100 │     │     │ "ETH" → 5   │     │     │     │
           └─────┴─────────────┴─────┴─────┴─────────────┴─────┴─────┴─────┘
```

Чтобы **найти** `d["BTC"]`, Python повторяет шаги 1–2, идёт прямо в ячейку 1 и сравнивает
ключ через `==` — совпал, отдаёт значение. Перебора нет.

**Коллизия** — два разных ключа попали в одну ячейку (хешей бесконечно много, ячеек — 8).
Есть два способа это пережить:

- **цепочки (chaining):** в ячейке лежит маленький список пар, по нему идут и сравнивают ключи —
  так устроена своя хеш-таблица в задаче t02;
- **открытая адресация (open addressing):** если ячейка занята, пробуют следующую по особому
  правилу, пока не найдут свободную — так делает CPython.

**Рост.** Когда таблица заполнена примерно на 2/3, Python выделяет таблицу побольше и
**перекладывает** все ключи (у них меняется `h % размер`). Как у `append` в списке, это редкое
O(n), а в среднем выходит O(1).

**Почему «в среднем»?** Если у всех ключей одинаковый хеш, все попадут в одну цепочку, и поиск
станет перебором — O(n). У встроенных типов хеши хорошие, на практике это не встречается.

```
                  в среднем   худший случай
d[k], k in d        O(1)          O(n)       все ключи в одной ячейке
d[k] = v            O(1)*         O(n)       * амортизированно, с учётом роста
del d[k]            O(1)          O(n)
перебор, копия      O(n)          O(n)
```

### 2. Требования к ключу

Ключ должен быть **хешируемым**: его `hash` не меняется, пока он лежит в словаре (C1, раздел 9).
Иначе после изменения ключ «потерялся» бы — Python искал бы его в другой ячейке.

```python
d = {}
d[(1, 2)] = "ok"        # tuple из чисел — можно
d["id"] = "ok"          # str — можно
d[[1, 2]] = "x"         # TypeError: unhashable type: 'list'
```

Равные ключи — это **один** ключ. `1 == 1.0 == True` и хеши у них равны:

```python
d = {1: "int", 1.0: "float", True: "bool"}
print(d)        # {1: 'bool'} — ключ остался первым, значение перезаписано последним
```

### 3. Порядок вставки (с Python 3.7)

Словарь **помнит порядок**, в котором ключи добавляли. Это гарантия языка с 3.7. Устроено так:
ключи и значения лежат в отдельном массиве **по порядку добавления**, а хеш-таблица хранит
только номера строк этого массива:

```
индексы (хеш-таблица):     [ · | 1 | · | · | 0 | · | · | · ]
                                 │           │
записи (по порядку):  0: hash, "ETH", 5   ◄──┘
                      1: hash, "BTC", 100 ◄──┘
```

Перебор идёт по массиву записей — отсюда порядок. Бонус: так меньше памяти, потому что пустые
ячейки хеш-таблицы — маленькие числа, а не целые пары.

- Перезапись значения **не меняет** позицию ключа.
- `del` + повторное добавление ставит ключ **в конец**.
- Сравнение `==` порядок **не учитывает**: `{"a": 1, "b": 2} == {"b": 2, "a": 1}` → `True`.

### 4. Чтение: `[]`, `get`, `in`

```python
order = {"id": 7, "status": "NEW"}

order["price"]               # KeyError: 'price'
order.get("price")           # None — без исключения
order.get("price", "0")      # '0' — своё значение по умолчанию
"status" in order            # True — in проверяет КЛЮЧИ, не значения
"NEW" in order               # False
"NEW" in order.values()      # True, но это O(n) — перебор значений
```

В тестах: `order["status"]` — когда поле **обязано** быть (упадёт KeyError, и это правильно).
`order.get(...)` — когда поле необязательное.

### 5. Запись и обновление

```python
d = {"a": 1}
d["b"] = 2                    # добавить или перезаписать
d.update({"a": 10, "c": 3})   # слить другой dict на месте → {'a': 10, 'b': 2, 'c': 3}
merged = d | {"d": 4}         # новый dict (3.9+), d не меняется
d |= {"e": 5}                 # то же на месте
d.setdefault("tags", []).append("x")   # если ключа нет — положить [] и вернуть его
```

`setdefault(k, default)` возвращает значение по ключу, а если ключа нет — сначала кладёт
`default`. Это способ группировать без `if`, но `defaultdict` (раздел 5) читается лучше.

### 6. Удаление

```python
d = {"a": 1, "b": 2}
d.pop("a")             # 1 — удалить и вернуть
d.pop("zzz")           # KeyError
d.pop("zzz", None)     # None — без ошибки
del d["b"]             # удалить, KeyError если нет
d.popitem()            # удалить и вернуть ПОСЛЕДНЮЮ пару (LIFO)
```

### 7. Перебор и views

```python
prices = {"BTC": 100, "ETH": 5}
for key in prices: ...                   # перебор ключей
for key, value in prices.items(): ...    # пары — распаковка (раздел 2)
for value in prices.values(): ...
```

`keys()`, `values()`, `items()` возвращают не списки, а **views** — «живые окна» в словарь.
Добавишь ключ — окно его покажет:

```python
keys = prices.keys()
prices["SOL"] = 1
print(keys)            # dict_keys(['BTC', 'ETH', 'SOL'])
```

`keys()` и `items()` умеют операции множеств: `d1.keys() & d2.keys()` — общие ключи.

### 8. Нельзя менять размер словаря во время перебора

```python
d = {"a": 1, "b": 0, "c": 0}
for k in d:
    if d[k] == 0:
        del d[k]       # RuntimeError: dictionary changed size during iteration
```

Менять **значения** при переборе можно, **добавлять и удалять ключи** — нет. Правильно:

```python
for k in list(d):                       # перебираем копию ключей
    if d[k] == 0:
        del d[k]

d = {k: v for k, v in d.items() if v != 0}   # или собрать новый словарь
```

### 9. Dict comprehension и полезные приёмы

```python
by_id = {u["id"]: u for u in users}               # индекс: поиск пользователя по id за O(1)
inverted = {v: k for k, v in codes.items()}       # поменять ключи и значения местами
counts = {}
for w in words:
    counts[w] = counts.get(w, 0) + 1               # подсчёт без Counter
```

`dict.fromkeys(keys, [])` кладёт **один и тот же** список под все ключи (C1, раздел 6).

---

**Частая ошибка.** Искать в списке словарей циклом внутри цикла:
`for o in orders: for u in users: if u["id"] == o["user_id"]` — это O(n·m). Сначала строят индекс
`users_by_id = {u["id"]: u for u in users}`, потом `users_by_id[o["user_id"]]` — O(n + m).

<details><summary>Проверь себя: что выведет?</summary>

```python
d = {"x": 1, "y": 2}
d["x"] = 10
del d["y"]
d["y"] = 3
print(list(d), d == {"y": 3, "x": 10})
```
`['x', 'y'] True`. Перезапись `x` позицию не меняет. `y` удалили и добавили заново — он в конце.
Сравнение словарей порядок не учитывает.
