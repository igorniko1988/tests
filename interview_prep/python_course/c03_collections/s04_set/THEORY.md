# C3 · Раздел 4. set — множество

[← раздел 3](../s03_dict/THEORY.md) · [оглавление урока](../README.md) · [раздел 5 →](../s05_counter_defaultdict/THEORY.md)

**Простыми словами.** Множество — это словарь **без значений**: только ключи. Та же
хеш-таблица, поэтому:
- каждый элемент встречается **один раз** — дубли отбрасываются сами;
- проверка `x in s` — **O(1)** в среднем (в списке — O(n));
- элементы должны быть **хешируемыми**;
- **порядка нет** — элементы лежат в ячейках по хешу, а не по времени добавления.

```python
ids = {3, 1, 3, 2}
print(len(ids))        # 3 — дубль 3 отброшен
print(2 in ids)        # True, за O(1)
ids.add(5)
ids.discard(100)       # удалить, если есть; нет — молча
ids.remove(100)        # KeyError — если нет
```

### 1. Пустое множество — только `set()`

```python
a = {}         # это dict!
b = set()      # пустое множество
c = {1}        # множество из одного элемента
```

### 2. Порядок не гарантирован

Порядок элементов в множестве зависит от хешей и истории вставок. Для маленьких int он
*выглядит* отсортированным (`hash(3) == 3`), для строк меняется **между запусками** программы:
хеш строк рандомизируется при старте Python (защита от атак на хеш-таблицы).

```python
print({"b", "a", "c"})     # сегодня {'c', 'a', 'b'}, завтра {'a', 'b', 'c'}
print(sorted({"b", "a"}))  # ['a', 'b'] — когда нужен порядок, сортируй явно
```

Поэтому в тестах никогда не сравнивай `list(some_set)` со списком — только `set == set` или
`sorted(...) == [...]`.

### 3. Операции множеств

```python
a = {1, 2, 3}
b = {2, 3, 4}

a | b     # {1, 2, 3, 4}   объединение — есть хотя бы в одном
a & b     # {2, 3}         пересечение — есть в обоих
a - b     # {1}            разность — есть в a, нет в b
a ^ b     # {1, 4}         симметричная разность — ровно в одном

{1, 2} <= a       # True — подмножество: все элементы слева есть в a
a >= {1}          # True — надмножество
a.isdisjoint({9}) # True — нет общих элементов
```

```
      a           b
   ┌─────────┬─────────┐
   │  1  ┌───┼───┐  4  │      a & b = {2, 3}       середина
   │     │ 2 │ 3 │     │      a - b = {1}          только слева
   │     └───┼───┘     │      b - a = {4}          только справа
   └─────────┴─────────┘      a ^ b = {1, 4}       края без середины
```

Методы делают то же, но принимают **любой iterable**: `a.union([5])`, `a.intersection("ab")`.
Операторы `|`, `&` требуют множество с обеих сторон (`{1} | [2]` → TypeError).

Сложность: `a & b` — O(min(len(a), len(b))): идём по меньшему и спрашиваем `in` у большего.

### 4. Где это в тестах AQA

```python
expected_ids = {1, 2, 3}
actual_ids = {u["id"] for u in resp.json()}       # set comprehension

missing = expected_ids - actual_ids     # кого не вернул API
extra = actual_ids - expected_ids       # кого вернул лишнего
assert not missing and not extra, f"missing={missing}, extra={extra}"

assert {"id", "status", "price"} <= order.keys()  # все обязательные поля есть в ответе
```

Сообщение с `missing` и `extra` в разы полезнее, чем `assert set(a) == set(b)`: сразу видно, что
не так.

### 5. Убрать дубли

```python
list(set(items))           # быстро, но порядок теряется
list(dict.fromkeys(items)) # порядок первого появления сохранён — ключи dict упорядочены
```

Если элементы нехешируемые (словари) — C1, задача t07 `dedupe`.

### 6. frozenset

Неизменяемое множество. Хешируемое — значит, может быть ключом словаря или элементом другого
множества. Пример: «пара пользователей без учёта порядка» — `frozenset({a, b})`.

```python
pairs = {frozenset({1, 2}), frozenset({2, 1})}
print(len(pairs))     # 1 — это одна пара
```

### 7. list против set для `in`

```python
banned = ["u1", "u2", ...]          # 10 000 элементов
for user in users:                  # 10 000 пользователей
    if user in banned: ...          # каждый in — до 10 000 сравнений → 10⁸ операций

banned = set(banned)                # один раз O(n)
for user in users:
    if user in banned: ...          # каждый in — O(1) → 10⁴ операций
```

Это одна из самых частых оптимизаций на лайвкодинге (трек A, A2 — хеширование).

---

**Частая ошибка.** `assert set(actual) == set(expected)` для проверки «в ответе те же элементы».
Множество **прячет дубли**: `[1, 1, 2]` и `[1, 2]` дадут одно и то же `{1, 2}`, и тест не заметит,
что API вернул пользователя дважды. Если важны дубли — сравнивай `Counter` (раздел 5) или `sorted`.

<details><summary>Проверь себя: что выведет?</summary>

```python
a = {1, 2, 3}
b = [3, 3, 4]
print(len(a | set(b)), a & set(b), a.union(b) == a | set(b))
```
`4 {3} True`. Из `b` получится `{3, 4}`. Объединение — `{1, 2, 3, 4}`, пересечение — `{3}`.
`union` принимает список напрямую.
</details>
