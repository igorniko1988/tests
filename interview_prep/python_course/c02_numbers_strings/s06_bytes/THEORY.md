# C2 · Раздел 6. str и bytes, кодировки

[← раздел 5](../s05_fstrings/THEORY.md) · [оглавление урока](../README.md) · [раздел 7 →](../s07_truthy/THEORY.md)

**Простыми словами.** Есть два разных типа «текста»:

- **`str`** — текст: последовательность **символов** Unicode («п», «€», «😀»). С ним работает
  твой код.
- **`bytes`** — последовательность **байтов** (чисел 0…255). Это то, что реально лежит в файле,
  летит по сети, приходит в теле HTTP-ответа.

Перевод между ними — **кодировка** (encoding). Самая распространённая — **UTF-8**: латиница
занимает 1 байт, кириллица — 2, знак евро — 3, эмодзи — 4.

```
        encode("utf-8")
 str  ─────────────────▶  bytes
 "п"                      b'\xd0\xbf'   (2 байта)
      ◀─────────────────
        decode("utf-8")
```

```python
text = "привет"
data = text.encode("utf-8")     # str → bytes
print(data)                     # b'\xd0\xbf\xd1\x80\xd0\xb8\xd0\xb2\xd0\xb5\xd1\x82'
print(len(text), len(data))     # 6 12 — 6 символов, но 12 байтов
print(data.decode("utf-8"))     # привет — bytes → str
```

---

### Что важно знать

- **`bytes` печатаются с префиксом `b`:** `b'hi'`. ASCII-символы видны как есть, остальные — `\xNN`.
- **Элемент bytes — число, а не символ:** `b"abc"[0]` → `97` (код буквы `a`).
- **`str` и `bytes` никогда не равны:** `b"hi" == "hi"` → `False`. И не складываются: `b"a" + "b"` → `TypeError`.
- **`len` считает разное:** символы у `str`, байты у `bytes`. Ограничение «поле не длиннее 255 байт»
  и «255 символов» — разные требования, это граничный случай для теста.

### Ошибки декодирования

Если байты не являются корректным UTF-8 (файл в другой кодировке, обрезанный ответ), `decode`
падает с `UnicodeDecodeError`. Параметр `errors` решает, что делать:

```python
raw = b"a\xffb"
raw.decode("utf-8")                     # UnicodeDecodeError
raw.decode("utf-8", errors="replace")   # 'a�b' — показывается как a�b
raw.decode("utf-8", errors="ignore")    # 'ab' — битый байт выброшен молча
```

`replace` лучше `ignore`: символ `�` в отчёте сразу показывает, что данные битые.

Если в строку закодировали одной кодировкой, а декодируют другой — получается «кракозябры»
(mojibake): `"привет".encode("utf-8").decode("cp1251")` → `'РїСЂРёРІРµС‚'`.

### Где это встречается в автотестах

```python
resp = requests.get(url)
resp.content     # bytes — сырое тело
resp.text        # str — декодировано по кодировке из заголовка Content-Type (или угадано)
resp.json()      # dict — разобранный JSON
resp.encoding    # 'utf-8' — какую кодировку requests решил использовать
```

- Сравниваешь тело с ожидаемым текстом — бери `resp.text`, а не `resp.content`.
- Файлы открывай с явной кодировкой: `open(path, encoding="utf-8")` — иначе на Windows
  возьмётся системная cp1251 и тест упадёт только там.
- Скачанный файл, картинку, PDF сравнивают как **bytes** (`"rb"`), без декодирования.
- Подпись HMAC (наш стенд, `X-Signature`) считается от **байтов** тела:
  `hmac.new(secret.encode(), body_bytes, "sha256")`. Перекодируешь тело — подпись не сойдётся.

---

**Частая ошибка.** Проверять `assert resp.content == "ok"` — bytes никогда не равны str, тест
падает «необъяснимо». Нужно `resp.text == "ok"` или `resp.content == b"ok"`.

<details><summary>Проверь себя: что выведет?</summary>

```python
s = "€5"
b = s.encode("utf-8")
print(len(s), len(b), b[-1], b.decode()[0])
```
`2 4 53 €`. Евро — 3 байта + цифра 1 байт = 4; последний байт — код символа `'5'` (53);
декодирование возвращает исходную строку.
