# C2 · Раздел 3. Decimal: деньги без потерь

[← раздел 2](../s02_float/THEORY.md) · [оглавление урока](../README.md) · [раздел 4 →](../s04_strings/THEORY.md)

**Простыми словами.** `decimal.Decimal` хранит число как **десятичные цифры**, а не двоичную
дробь. 0.1 в нём — это ровно «ноль, запятая, один». Поэтому для денег, цен, количеств лотов и
всего, где важна каждая копейка, используют Decimal. На нашем стенде все суммы — Decimal на
сервере и **строка** в API (`"balance": "100.50"`) — именно чтобы не терять точность.

```python
from decimal import Decimal

print(Decimal("0.1") + Decimal("0.2"))                    # 0.3
print(Decimal("0.1") + Decimal("0.2") == Decimal("0.3"))  # True
```

---

### Главное правило: Decimal создают из строки

```python
Decimal("0.1")   # 0.1 — ровно то, что написано
Decimal(0.1)     # 0.1000000000000000055511151231257827021181583404541015625
```

`Decimal(0.1)` получает **уже испорченный** float и честно копирует его ошибку до последней цифры.
Decimal из float не «чинит» float. Поэтому: из строки (`Decimal("0.1")`), из int (`Decimal(5)`)
или из ответа API, который пришёл строкой.

### Арифметика

```python
price = Decimal("19.99")
qty = 3
print(price * qty)               # 59.97 — с int складывать и умножать можно
print(Decimal("1.10") * 3)       # 3.30 — Decimal помнит число знаков после запятой
print(Decimal("1.5") + 0.5)      # TypeError — с float нельзя, чтобы неточность не пролезла тихо
```

`Decimal("2.50") == Decimal("2.5")` → `True`: значения равны. Но `str()` у них разный
(`"2.50"` и `"2.5"`) — запись хранит и количество знаков.

### Округление: `quantize`

Чтобы округлить Decimal до нужного числа знаков, его «подгоняют под образец» методом
`quantize`. Образец `Decimal("0.01")` значит «два знака после запятой»:

```python
from decimal import Decimal, ROUND_HALF_UP, ROUND_HALF_EVEN, ROUND_DOWN

x = Decimal("2.665")
x.quantize(Decimal("0.01"))                           # 2.66 — по умолчанию ROUND_HALF_EVEN
x.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)   # 2.67 — «как в школе»
x.quantize(Decimal("0.01"), rounding=ROUND_DOWN)      # 2.66 — просто отбросить
```

| Режим | Что делает с половиной | 2.665 → | 2.675 → |
|---|---|---|---|
| `ROUND_HALF_EVEN` (по умолчанию, «банковское») | к чётной последней цифре | 2.66 | 2.68 |
| `ROUND_HALF_UP` («школьное») | всегда вверх (от нуля) | 2.67 | 2.68 |
| `ROUND_DOWN` | отбросить лишнее (к нулю) | 2.66 | 2.67 |

**Какой режим правильный** — решает бизнес, а не тестировщик. Это вопрос к аналитику или
документации: «до скольких знаков и как округляем комиссию?». Задача теста — проверить, что
сервис следует правилу, особенно **на половинках** (x.xx5) — это граничное значение.

### Decimal ↔ строка ↔ float

```python
d = Decimal("10.50")
str(d)        # '10.50' — точное представление, с нулём в конце
float(d)      # 10.5   — уже float, ноль пропал, точность может уйти
Decimal(str(some_float))   # если пришёл float — через str: Decimal(str(0.1)) → 0.1
```

### Контекст и точность

У Decimal есть «контекст» — глобальные настройки: точность (28 значащих цифр по умолчанию) и
режим округления **арифметики**. Например, `Decimal(1) / Decimal(3)` даст 28 троек. Для денег
обычно хватает умолчания + явного `quantize` в конце расчёта.

---

**Частая ошибка.** Посчитать сумму во float, а потом сделать `Decimal(total)` — ошибка уже
внутри. Переводи в Decimal **на входе** (из строки), считай в Decimal, округляй `quantize` в конце.

<details><summary>Проверь себя: что выведет?</summary>

```python
from decimal import Decimal, ROUND_HALF_UP
total = sum([Decimal("0.125"), Decimal("0.125")])
print(total, total.quantize(Decimal("0.01")), total.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))
```
`0.250 0.25 0.25`. Сумма 0.250 — половинки нет, оба режима дают 0.25. А для `Decimal("0.125")`
отдельно: HALF_EVEN → 0.12 (2 — чётная), HALF_UP → 0.13.
</details>
