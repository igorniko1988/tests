# C2 · Раздел 9. Шпаргалка и собес

## Шпаргалка

1. `int` не переполняется. `/` всегда float, `//` округляет вниз (к −∞), `%` берёт знак делителя.
2. `int(x)` отбрасывает дробную часть к нулю; `int("3.5")` — ValueError.
3. float хранится в двоичной системе с ошибкой: `0.1 + 0.2 != 0.3`. Сравнение — `math.isclose`, в тестах `pytest.approx`.
4. `round()` банковский (половина к чётному): `round(2.5) == 2`. `round(2.675, 2) == 2.67` из-за float.
5. NaN не равен себе: проверка `math.isnan`. float переполняется в `inf`.
6. Деньги — `Decimal`, и только из строки: `Decimal("0.1")`, не `Decimal(0.1)`. С float не складывается.
7. Округление денег — `quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`; режим берётся из требований.
8. Строки неизменяемы; срез не падает за границами; `split()` без аргумента выбрасывает пустые куски.
9. Сборка строки — `"".join(parts)`, не `+=` в цикле (O(n²)).
10. f-строки: `:.2f`, `:,`, `:<10`, `:>10`, `:^10`, `!r`, `{x=}`.
11. `str` — символы, `bytes` — байты; `encode`/`decode`, UTF-8; `errors="replace"`. str и bytes не равны.
12. Falsy: `False`, `None`, нули, пустые коллекции и строки. `"0"`, `"False"`, `[0]` — truthy.
13. `a or b` / `a and b` возвращают операнд; `x or default` ломается на 0 и `""` — используй `is None`.
14. `bool` — подкласс `int`: `True + True == 2`, `True == 1`.

## Собес

- **Почему `0.1 + 0.2 != 0.3`? Как сравнивать float?**
  float хранит числа в двоичной системе по IEEE 754, а 0.1 и 0.2 в двоичной — бесконечные дроби,
  они обрезаются и хранятся с маленькой ошибкой. При сложении ошибки суммируются. Сравнивать
  float через `==` нельзя: используют `math.isclose` или в тестах `pytest.approx` с допуском.

- **Как работать с деньгами в Python?**
  Через `decimal.Decimal`, созданный из строки или int: он хранит десятичные цифры точно. Считаю
  всё в Decimal, в конце округляю `quantize` до нужного числа знаков с режимом округления из
  требований (часто `ROUND_HALF_UP`). В API суммы передают строкой, чтобы клиенты не потеряли
  точность. Decimal из float создавать нельзя — он скопирует ошибку float.

- **Как округляет `round()`? Почему `round(2.5) == 2`?**
  По правилу банковского округления: половина округляется к ближайшему чётному. Так ошибки
  округления вверх и вниз в среднем компенсируются. Плюс float-эффект: `round(2.675, 2) == 2.67`,
  потому что 2.675 хранится как 2.67499… Для «школьного» округления — Decimal с `ROUND_HALF_UP`.

- **Чем `/` отличается от `//`? Что даст `-7 // 2` и `-7 % 2`?**
  `/` — обычное деление, всегда возвращает float. `//` — целочисленное деление с округлением вниз,
  к минус бесконечности: `-7 // 2 == -4`. Остаток берёт знак делителя: `-7 % 2 == 1`, так чтобы
  выполнялось `a == (a // b) * b + a % b`.

- **Чем `str` отличается от `bytes`?**
  `str` — текст из символов Unicode, `bytes` — последовательность байтов 0…255, то, что хранится
  в файлах и передаётся по сети. Переход — `encode`/`decode` с кодировкой, обычно UTF-8. Они не
  равны и не складываются. В requests `resp.content` — bytes, `resp.text` — str.

- **Почему строки неизменяемы и как эффективно собрать строку?**
  Неизменяемость делает строки хешируемыми (ключи dict), безопасными для передачи и позволяет
  Python переиспользовать их. Следствие: `s += x` в цикле каждый раз копирует строку — O(n²).
  Правильно собрать части в список и сделать `"".join(parts)` — O(n).

- **Что такое truthy и falsy? Что вернёт `0 or "x"`?**
  Любой объект в условии ведёт себя как истина или ложь. Ложны `False`, `None`, нули, пустые
  строки и коллекции, всё остальное истинно. `or` и `and` возвращают не bool, а один из операндов:
  `0 or "x"` вернёт `"x"`. Из-за этого `value or default` ломается, если 0 или пустая строка —
  допустимые значения; тогда пишут `default if value is None else value`.

- **Что такое f-строки и чем они лучше `%` и `format`?**
  Строки с префиксом `f`, где в `{}` подставляется любое выражение, а после двоеточия — формат
  (`:.2f`, `:>10`, `:,`). Они читаемее и быстрее. `{x=}` выводит имя и значение — удобно для
  отладки, `!r` — repr с кавычками, полезно в сообщениях ассертов.

- **Какие граничные значения проверишь для поля «сумма»?**
  0, отрицательное, минимальный шаг (0.01), значение с лишним знаком (0.001), половинку на
  округлении (x.xx5), очень большое, нечисловые строки, `"NaN"`, `"Infinity"`, `"1e3"`, пустое и
  `null`. И то, что сумма приходит в ответе строкой с правильным числом знаков.
