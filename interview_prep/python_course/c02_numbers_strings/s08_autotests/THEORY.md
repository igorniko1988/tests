# C2 · Раздел 8. Где это ломает автотесты

[← раздел 7](../s07_truthy/THEORY.md) · [оглавление урока](../README.md) · [раздел 9 →](../s09_cheatsheet/THEORY.md)

**Простыми словами.** Числа и строки — это то, что тесты проверяют чаще всего: суммы, цены,
статусы, сообщения. Ошибки в этом месте дают либо **флейки** (float), либо **ложные зелёные**
(неправильная проверка истинности), либо «необъяснимые» падения (str против bytes). Ниже —
типичные ситуации на примере нашего стенда «мини-биржа».

---

### 1. Деньги приходят строкой — сравнивай Decimal

Стенд отдаёт суммы строкой: `{"balance": "100.50"}`. Три способа сравнить и два из них плохие:

```python
balance = resp.json()["balance"]          # '100.50'

assert balance == 100.5                   # ✗ str никогда не равна float
assert float(balance) == 100.5            # ✗ работает, пока числа «удобные»; после расчётов — флейк
assert Decimal(balance) == Decimal("100.5")   # ✓ точное сравнение значений
```

Если важен и **формат** ответа (ровно два знака) — это отдельная, явная проверка:
`assert balance == "100.50"` или регуляркой `r"^\d+\.\d{2}$"`.

### 2. Ожидаемое значение считай в Decimal

```python
# баланс после покупки 3 лотов по 19.99 с комиссией 0.1%
expected = Decimal("1000") - Decimal("19.99") * 3 * Decimal("1.001")
expected = expected.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)   # правило округления — из требований
assert Decimal(resp.json()["balance"]) == expected
```

Тест, который считает ожидаемое во float, сам становится источником ошибки на копейку.

### 3. JSON-числа превращаются во float

```python
json.loads('{"p": 0.1}')["p"] + 0.2                       # 0.30000000000000004
json.loads('{"p": 0.1}', parse_float=Decimal)["p"]        # Decimal('0.1')
resp.json(parse_float=Decimal)                            # requests пробрасывает параметры в json.loads
```

Если API отдаёт деньги **числом**, а не строкой — это уже повод для баг-репорта (потеря точности
на стороне клиентов), и в тесте их надо разбирать через `parse_float=Decimal`.

### 4. float в тестах — только с допуском

Метрики, проценты, время ответа — float, точного равенства не бывает:

```python
assert stats["fill_ratio"] == pytest.approx(0.333, rel=1e-3)
assert elapsed == pytest.approx(1.0, abs=0.2)
```

### 5. Проверка истинности вместо проверки значения

```python
data = {"count": 0, "items": []}
assert data.get("count")      # ✗ падает: 0 ложен — хотя ответ правильный
assert data["items"]          # ✗ падает на пустом списке — а пустой список может быть ожидаемым
assert "count" in data and data["count"] == 0     # ✓ проверяем ровно то, что хотим
```

Обратная ловушка — **ложный зелёный**: `assert resp.json()["error"]` пройдёт при
`"error": "false"` (непустая строка truthy).

### 6. bytes против str

```python
assert resp.content == "ok"       # ✗ всегда False
assert resp.text == "ok"          # ✓
```

### 7. Граничные значения для чисел и строк

Тест-дизайн по теме урока — классы эквивалентности и границы (F2):

- **числа:** 0, отрицательное, минимальный шаг (0.01), x.xx5 (половинка при округлении), очень
  большое, больше знаков, чем разрешено (`"1.001"` при шаге 0.01), `"1e3"`, `"NaN"`, `"Infinity"`;
- **строки:** пустая, пробелы по краям, только пробелы, кириллица и эмодзи (длина в символах и
  байтах!), максимальная длина и +1, спецсимволы и кавычки.

---

**Частая ошибка.** «Подогнать» проверку под ответ — `assert round(float(balance), 2) == 100.5` —
вместо того чтобы выяснить правило округления. Тест должен проверять требование, а не текущее
поведение сервиса.
