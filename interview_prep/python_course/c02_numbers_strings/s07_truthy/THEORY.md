# C2 · Раздел 7. bool, truthy и falsy, and / or

[← раздел 6](../s06_bytes/THEORY.md) · [оглавление урока](../README.md) · [раздел 8 →](../s08_autotests/THEORY.md)

**Простыми словами.** В `if x:` Python не требует, чтобы `x` был именно `True` или `False`. Любой
объект можно проверить «на истинность». Объекты, которые в условии ведут себя как ложь,
называют **falsy**, остальные — **truthy**.

**Falsy — короткий список, его стоит выучить:**
- `False`, `None`
- ноль любого числового типа: `0`, `0.0`, `Decimal("0")`
- пустые коллекции и строки: `""`, `[]`, `()`, `{}`, `set()`, `b""`, `range(0)`

**Всё остальное — truthy.** В том числе ловушки:

```python
bool("0")        # True  — непустая строка
bool("False")    # True  — непустая строка
bool([0])        # True  — список с одним элементом
bool(" ")        # True  — пробел — это символ
bool(float("nan"))   # True
```

Свои классы могут управлять этим через `__bool__` или `__len__` (C9).

### `and` и `or` возвращают операнд, а не bool

Это частый вопрос «что выведет». `or` и `and` вычисляются **слева направо и лениво** (останавливаются,
как только результат понятен) и возвращают **последнее вычисленное значение**:

- **`a or b`** — если `a` truthy, вернуть `a`; иначе вернуть `b`.
- **`a and b`** — если `a` falsy, вернуть `a`; иначе вернуть `b`.

```python
print(0 or "default")      # default — 0 ложен, берём второе
print(5 or "default")      # 5       — 5 истинно, второе даже не вычисляется
print("" and "x")          # ''      — первое ложно, оно и возвращается
print("a" and "x")         # x       — первое истинно, возвращается второе
print(None or 0 or [])     # []      — все ложны → последнее
```

Ленивость полезна: `user and user.name` не упадёт на `None` — до `.name` дело не дойдёт.

### Ловушка `x or default`

Идиома «значение или значение по умолчанию» ломается, когда **валидное значение — falsy**:

```python
def set_qty(qty=None):
    return qty or 1        # хотели: «если не передали — 1»

set_qty()     # 1 ✓
set_qty(0)    # 1 ✗ — ноль заменился на 1!
```

Правильно — проверять именно `None`:

```python
def set_qty(qty=None):
    return 1 if qty is None else qty
```

То же в тестах: `assert data.get("count")` упадёт на `{"count": 0}`, хотя поле есть и значение
корректно. Проверяй наличие (`"count" in data`) и значение (`data["count"] == 0`) отдельно.

### `bool` — подкласс `int`

```python
True + True           # 2
True == 1             # True
sum(x > 0 for x in nums)   # сколько положительных — частый приём
{1: "a", True: "b"}   # {1: 'b'} — один и тот же ключ (C1, раздел 9)
```

### Сравнения

```python
None == False         # False — None ложен, но НЕ равен False
[] == False           # False — пустой список ложен, но не равен False
not None              # True
1 < x < 10            # цепочка: (1 < x) and (x < 10)
```

**Правила стиля:**
- `if items:` вместо `if len(items) > 0:` — проверка на пустоту.
- `if x is None:` вместо `if x == None:` и вместо `if not x:` (когда 0 и `""` — допустимые значения).
- `if flag:` вместо `if flag == True:`.

---

**Частая ошибка.** `if not response_body:` для проверки «ответа нет» — а пришёл валидный
пустой список `[]` или `0`, и тест решил, что ответа нет. Проверяй то, что имеешь в виду: `is None`,
`== []`, `== 0`.

<details><summary>Проверь себя: что выведет?</summary>

```python
a = [] or [0] or None
b = 0 and 1/0
print(a, b)
```
`[0] 0`. `[]` ложен → берём `[0]`, он истинен → возвращаем его. `0 and …` — первый операнд ложен,
`1/0` не вычисляется (ленивость), ошибки нет.
</details>
