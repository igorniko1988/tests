# C1. Объекты, имена и ссылки

Визуализатор: `visual/objects_refs.html` (онлайн-ссылка в README урока).
Дальше: `quiz.py` (15 «что выведет»), потом `tasks/` (10 задач).

**Смысл темы.** В Python переменная — не коробка со значением, а имя (ярлык), привязанное к объекту.
Почти все ловушки «что выведет» на собесе растут отсюда: два имени на один список, `+=` то меняет
объект, то создаёт новый, копия оказывается неглубокой, аргумент по умолчанию живёт между вызовами.
В автотестах это выглядит как «тест проходит один раз и падает во второй», «фикстура испортила
данные соседнему тесту», «мок записал уже изменённый объект».

---

### 1. Имя и объект

```python
a = [1, 2]
b = a                    # второе имя на ТОТ ЖЕ список, копии нет
print(id(a) == id(b))    # True
print(type(a), a)        # <class 'list'> [1, 2]
b.append(3)
print(a)                 # [1, 2, 3]
```

- **объект:** у каждого есть идентичность (`id`), тип (`type`) и значение.
- **присваивание `b = a`:** ничего не копирует, а привязывает второе имя к тому же объекту.
- **контейнеры:** в списке лежат не сами значения, а ссылки на объекты.
- **`del a`:** удаляет имя, а не объект; объект живёт, пока на него есть хоть одна ссылка.

### 2. Изменяемые и неизменяемые типы

| Неизменяемые (immutable) | Изменяемые (mutable) |
|---|---|
| `int`, `float`, `bool`, `str`, `bytes`, `tuple`, `frozenset`, `None` | `list`, `dict`, `set`, `bytearray`, объекты своих классов |

```python
s = "abc"
s.upper()        # создаёт НОВУЮ строку, s не тронута
print(s)         # abc

nums = [3, 1]
r = nums.sort()  # меняет сам список
print(nums, r)   # [1, 3] None
```

- **неизменяемый:** любая «операция изменения» возвращает новый объект, старый остаётся как был.
- **изменяемый:** методы меняют объект на месте и обычно возвращают `None` (`sort`, `append`, `update`).
- **tuple:** неизменяем сам кортеж (набор ссылок), но изменяемые объекты внутри него менять можно.

### 3. `a = a + b` против `a += b`

```python
a = [1]; b = a
a = a + [2]          # + всегда создаёт новый список
print(a, b)          # [1, 2] [1]

a = [1]; b = a
a += [2]             # list.__iadd__ расширяет ТОТ ЖЕ список
print(a, b)          # [1, 2] [1, 2]

x = (1,); y = x
x += (2,)            # у tuple нет __iadd__ → новый кортеж
print(x, y)          # (1, 2) (1,)

t = (1, [2])
try:
    t[1] += [3]      # список расширился, потом присваивание в кортеж упало
except TypeError:
    print("TypeError")
print(t)             # (1, [2, 3])
```

- **`+`:** всегда новый объект.
- **`+=` у изменяемых:** меняет объект на месте (`__iadd__`), все имена видят изменение.
- **`+=` у неизменяемых:** создаёт новый объект и переклеивает только это имя.
- **`t[1] += [3]`:** это два действия: `t[1].__iadd__([3])` (успешно), затем `t[1] = ...` (TypeError).

### 4. `is` и `==`

```python
a = [1, 2]
b = [1, 2]
print(a == b, a is b)    # True False

x = 256; y = 256
print(x is y)            # True — кэш малых чисел CPython (-5..256)

value = None
print(value is None)     # True
```

- **`==`:** равны ли значения, вызывает `__eq__`, его можно переопределить.
- **`is`:** один ли это объект (одинаковые `id`), переопределить нельзя.
- **малые int и короткие строки:** CPython их кэширует, поэтому `is` иногда «работает» — это деталь реализации, полагаться нельзя.
- **`is None`:** `None` — единственный объект своего типа, а `==` может быть переопределён, поэтому для `None` всегда `is`.

### 5. Поверхностная и глубокая копия

```python
import copy

src = [[1, 2], [3]]
alias = src                 # не копия
shallow = src.copy()        # то же: list(src), src[:], copy.copy(src)
deep = copy.deepcopy(src)

src[0].append(99)
print(alias[0], shallow[0], deep[0])   # [1, 2, 99] [1, 2, 99] [1, 2]

shallow.append([4])
print(len(src), len(shallow))          # 2 3

grid = [[0] * 3] * 3        # три ссылки на ОДИН внутренний список
grid[0][0] = 1
print(grid)                 # [[1, 0, 0], [1, 0, 0], [1, 0, 0]]

grid = [[0] * 3 for _ in range(3)]   # правильно: три разных списка
```

- **поверхностная (shallow):** новый внешний контейнер, внутри ссылки на те же объекты.
- **глубокая (deep):** рекурсивно копирует всё вложенное, справляется даже с циклическими ссылками.
- **`[[0] * 3] * 3`:** `*` повторяет ссылки; `[0] * 3` безопасен, потому что `int` неизменяем.
- **словари:** `d.copy()`, `dict(d)`, `{**d}` — тоже поверхностные.

### 6. Изменяемый аргумент по умолчанию

```python
def add(item, bucket=[]):
    bucket.append(item)
    return bucket

print(add(1))             # [1]
print(add(2))             # [1, 2]  — тот же список!
print(add.__defaults__)   # ([1, 2],)


def add(item, bucket=None):     # правильный вариант
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

- **когда создаётся:** значение по умолчанию вычисляется один раз, когда выполняется `def`, а не при каждом вызове.
- **где живёт:** в `add.__defaults__`, поэтому изменения копятся между вызовами.
- **фикс:** по умолчанию `None`, новый объект создаём внутри функции.
- **dataclass:** `roles: list = []` даже не даст создать класс (ValueError), нужно `field(default_factory=list)`.

### 7. Как передаются аргументы

```python
def change(lst, n):
    lst.append(1)   # меняем объект вызывающего — видно снаружи
    lst = [0]       # переклеиваем ЛОКАЛЬНОЕ имя — снаружи не видно
    n += 1          # int неизменяем: новый объект, только локально

nums, k = [], 5
change(nums, k)
print(nums, k)      # [1] 5
```

- **call by sharing:** функция получает ссылку на тот же объект, что и вызывающий код.
- **мутация видна снаружи:** `append`, `update`, `obj.attr = ...` меняют общий объект.
- **переприсваивание параметра не видно снаружи:** меняется только локальное имя.
- **на собесе:** «не по значению и не по ссылке, а по ссылке на объект (pass by object reference)».

### 8. Хешируемость

```python
d = {}
d[(1, 2)] = "ok"
# d[[1, 2]] = "x"       # TypeError: unhashable type: 'list'
# d[(1, [2])] = "x"     # TypeError: unhashable type: 'list'

print(hash(1) == hash(1.0) == hash(True))   # True
print({1: "a", 1.0: "b", True: "c"})        # {1: 'c'}
```

- **хешируемый объект:** его `hash` не меняется за время жизни и согласован с `==` (равные → одинаковый hash).
- **ключи dict и элементы set:** только хешируемые; встроенные изменяемые типы — нет.
- **tuple:** хешируем, только если хешируемо всё внутри.
- **`1`, `1.0`, `True`:** равны и имеют одинаковый hash, значит это один ключ; остаётся первый ключ и последнее значение.
- **свои классы:** по умолчанию хешируются по `id`; если переопределить `__eq__` без `__hash__`, объект станет нехешируемым (подробно в C9).

### 9. Где это ломает автотесты

```python
BASE_USER = {"email": "a@b.c", "roles": ["user"]}

def test_admin():
    user = BASE_USER.copy()          # поверхностная копия
    user["roles"].append("admin")    # испортили общий BASE_USER!

def test_user():
    assert BASE_USER["roles"] == ["user"]   # падает, если test_admin шёл раньше


from unittest.mock import Mock
m = Mock()
payload = {"qty": 1}
m(payload)
payload["qty"] = 5
print(m.call_args)                   # call({'qty': 5}) — мок хранит ссылку
```

- **общие данные:** шаблон тела запроса копируй через `copy.deepcopy` или собирай фабрикой.
- **фикстура со scope="session":** если отдаёт изменяемый объект, один тест портит его всем остальным.
- **моки:** `call_args` хранит ссылки, а не снимки; меняешь объект после вызова — меняется «история».
- **симптом:** тест зелёный один и красный в общем прогоне (или зависит от порядка) — первым делом ищи общий изменяемый объект.

### Собес

- **Чем изменяемые типы отличаются от неизменяемых?** Изменяемый объект можно поменять на месте (`list`, `dict`, `set`), все ссылки на него увидят изменение. Неизменяемый (`int`, `str`, `tuple`, `frozenset`) поменять нельзя: «изменение» создаёт новый объект. Отсюда хешируемость: ключами dict могут быть только неизменяемые.
- **`is` или `==`?** `==` сравнивает значения через `__eq__`, `is` проверяет, что это один объект. `is` используют для синглтонов (`None`), потому что это быстро и `__eq__` нельзя подменить. Для чисел и строк `is` не используют: совпадения из-за кэша CPython — деталь реализации.
- **Shallow copy и deep copy?** Поверхностная создаёт новый контейнер со ссылками на те же вложенные объекты; глубокая рекурсивно копирует всё. Разница видна на вложенных изменяемых структурах: шаблон JSON-тела в тестах копируют глубоко.
- **Что не так с `def f(x=[])`?** Значение по умолчанию создаётся один раз при `def` и хранится в `f.__defaults__`, поэтому список копится между вызовами. Правильно: `x=None` и внутри `if x is None: x = []`.
- **Python передаёт по ссылке или по значению?** По ссылке на объект (call by sharing): функция получает ссылку на тот же объект. Изменение изменяемого объекта видно снаружи, а переприсваивание параметра — нет.
- **Почему `list` не может быть ключом dict, а `tuple` может?** Ключ ищется по hash; если бы объект менялся, его hash менялся бы и ключ «потерялся» бы. Кортеж хешируем, только если всё внутри хешируемо: `(1, [2])` ключом быть не может.
- **Что выведет `grid = [[0]*3]*3; grid[0][0] = 1`?** `[[1, 0, 0], [1, 0, 0], [1, 0, 0]]`: внешний `*` повторил ссылку на один и тот же внутренний список. Правильно: `[[0]*3 for _ in range(3)]`.
- **Почему `a = a + b` и `a += b` для списков ведут себя по-разному?** `+` создаёт новый список, `+=` вызывает `__iadd__` и расширяет существующий, поэтому другие имена на этот список видят изменение. Для кортежей и строк `+=` всегда создаёт новый объект.
- **Где это встречается в автотестах?** Общие тестовые данные, которые один тест мутирует, фикстуры с широким scope, отдающие изменяемые объекты, моки, хранящие ссылку на аргумент, и хелперы с изменяемым значением по умолчанию. Защита: глубокие копии, фабрики данных, `None` по умолчанию.
