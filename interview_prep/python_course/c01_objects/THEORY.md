**Смысл темы.** Это фундамент всего Python. Если понять одну мысль — *переменная это имя,

по умолчанию → передача в функцию → хешируемость → автотесты → шпаргалка → собес.

### 1. Что такое объект

**Простыми словами.** В Python всё — объекты: число `5`, строка `"hi"`, список `[1, 2]`,
функция `len`, даже `None` и сам класс `int`. Объект — это «вещь», которая лежит в памяти.
У любого объекта есть ровно три характеристики:

1. **Идентичность (`id`)** — «номер паспорта» объекта. Пока объект жив, его `id` не меняется,
   и у двух живых объектов `id` не совпадает никогда. В CPython это адрес в памяти.
2. **Тип (`type`)** — что это за вещь и что с ней можно делать: у списка есть `append`, у числа нет.
   Тип объекта тоже никогда не меняется.
3. **Значение** — содержимое. У одних объектов его можно менять (список), у других нельзя (число, строка).

```python
nums = [1, 2]
print(id(nums))      # 4371203456   (у тебя будет другое число — это адрес)
print(type(nums))    # <class 'list'>
print(nums)          # [1, 2]       — значение

nums.append(3)
print(id(nums))      # 4371203456   — тот же объект, тот же id
print(nums)          # [1, 2, 3]    — значение изменилось

print(type(len), type(None), type(int))
# <class 'builtin_function_or_method'> <class 'NoneType'> <class 'type'>
```

**Что запомнить.** Значение может меняться, а `id` и `type` — никогда. Если после какой-то
операции `id` стал другим, значит это уже **другой объект**, а не изменённый старый.
Этим приёмом (сравнить `id` до и после) удобно проверять себя во всех следующих разделах.

**Частая ошибка.** Думать, что `id` — это «значение» или что одинаковые значения дают одинаковый
`id`. Два списка `[1, 2]` и `[1, 2]` равны, но это два разных объекта с разными `id`.

<details><summary>Проверь себя: что изменится — id, type или значение?</summary>

`s = [5]; s[0] = 7` — изменилось только значение, `id` и `type` те же.
</details>

### 2. Переменная — это имя, а не коробка

**Простыми словами.** Во многих языках (C, Java для примитивов) переменная — это коробка:
`a = 5` кладёт пятёрку в коробку `a`, а `b = a` кладёт в коробку `b` **копию** пятёрки.
В Python не так. Переменная — это **ярлык (стикер)**, который приклеивается к объекту.
Объект один, ярлыков на нём может быть сколько угодно.

Присваивание `имя = выражение` всегда делает две вещи:
1. вычисляет правую часть — получается объект (новый или уже существующий);
2. приклеивает имя слева к этому объекту. Если имя уже было приклеено к чему-то, его
   **переклеивают**, а старый объект при этом никак не меняется.

Присваивание **никогда ничего не копирует**. Это главное правило урока.

```python
a = [1, 2]       # создан список, на него приклеен ярлык a
b = a            # правая часть — это объект, на который смотрит a. Приклеиваем к нему b
b.append(3)      # меняем объект через ярлык b
print(a)         # [1, 2, 3] — a смотрит на тот же объект
print(a is b)    # True — это один объект
```

Как это выглядит в памяти:

```
 имена        объекты
 a ──┐
     ├─────▶  list [1, 2, 3]
 b ──┘
```

Теперь переклеим `b`:

```python
b = [9]          # создан НОВЫЙ список, ярлык b переклеен на него
print(a, b)      # [1, 2, 3] [9] — a не изменился
```

```
 a ──────▶  list [1, 2, 3]
 b ──────▶  list [9]
```

**Два разных действия, которые нужно различать всегда.** Почти каждая ловушка урока — это
путаница между ними:

- **мутация (изменить объект):** `b.append(3)`, `b[0] = 7`, `b.sort()`, `d["k"] = 1`, `obj.x = 5`.
  Объект тот же, изменение видят **все** имена, приклеенные к нему.
- **переприсваивание (переклеить имя):** `b = [9]`, `b = b + [1]`. Меняется только то, куда
  смотрит **это одно** имя; объект, на который оно смотрело раньше, не трогается.

`del a` — это тоже действие с именем: ярлык снимается, а объект продолжает жить, пока на него
смотрит хоть одно другое имя (или контейнер). Когда ссылок не остаётся, Python удаляет объект
сам (подробно — в уроке C12 про память).

**Частая ошибка.** «Я сделал `backup = data`, чтобы сохранить данные, потом поменял `data`,
а бэкап тоже поменялся». Это не бэкап, а второй ярлык. Нужна копия (раздел 6).

<details><summary>Проверь себя: что выведет?</summary>

```python
x = {"a": 1}
y = x
y = {"b": 2}
print(x)
```
`{'a': 1}`. Строка `y = {"b": 2}` — переприсваивание: ярлык `y` переклеен на новый словарь,
объект под `x` не тронут. Если бы было `y["b"] = 2` (мутация), вывод был бы `{'a': 1, 'b': 2}`.
</details>

### 3. Изменяемые и неизменяемые объекты

**Простыми словами.** Объект называется **изменяемым** (mutable), если его значение можно
поменять «на месте» — не создавая новый объект. **Неизменяемый** (immutable) объект поменять
нельзя вообще: любая операция, которая выглядит как изменение, на самом деле создаёт
**новый** объект.

| Неизменяемые (immutable) | Изменяемые (mutable) |
|---|---|
| `int`, `float`, `complex`, `bool`, `str`, `bytes`, `tuple`, `frozenset`, `None` | `list`, `dict`, `set`, `bytearray`, объекты твоих классов (по умолчанию) |

**Как «меняется» неизменяемое число.** Пятёрка не может стать шестёркой. Строка `x = x + 1`
создаёт **новый** объект `6` и переклеивает на него ярлык `x`:

```python
x = 5
print(id(x))     # 4341114288
x = x + 1
print(id(x))     # 4341114320 — другой id, значит другой объект
```

```
 до:     x ──▶ 5
 после:  x ──▶ 6        (5 никто не менял, ярлык x просто переклеили)
```

**Строки тоже неизменяемы.** Все методы строк возвращают **новую** строку и не трогают исходную:

```python
s = "hello"
s.upper()            # вернула "HELLO", но результат никуда не сохранили
print(s)             # hello
s = s.upper()        # правильно: сохранить результат (переклеить имя)
print(s)             # HELLO

s[0] = "J"           # TypeError: 'str' object does not support item assignment
```

**Методы изменяемых объектов обычно возвращают `None`.** Это сделано специально: так Python
подсказывает «я изменил объект на месте, нового объекта нет».

```python
nums = [3, 1, 2]
result = nums.sort()     # сортирует сам список
print(nums, result)      # [1, 2, 3] None

nums = nums.sort()       # частая ошибка: nums теперь None!
nums = sorted([3, 1, 2]) # sorted() — функция, она возвращает НОВЫЙ список
```

**Кортеж: неизменяем «каркас», а не содержимое.** Кортеж хранит ссылки на объекты, и
неизменяемы именно эти ссылки: нельзя заменить элемент, добавить или удалить. Но если ссылка
ведёт на изменяемый объект, сам этот объект менять можно:

```python
t = (1, [2])
t[1].append(3)       # можно: меняем список, на который ссылается кортеж
print(t)             # (1, [2, 3])
t[1] = [0]           # нельзя: TypeError — это замена ссылки внутри кортежа
```

```
 t ──▶ tuple ( ●1 , ● ) 
                    └──▶ list [2, 3]    ← этот список изменяемый
```

**Зачем вообще нужны неизменяемые объекты.**
- Их безопасно передавать куда угодно: никто не испортит строку или число «у тебя за спиной».
- Только их можно использовать как ключи словаря и элементы множества (раздел 9).
- Python может переиспользовать один объект вместо создания многих (кэш малых чисел, раздел 5).

**Частая ошибка.** `name.strip()` или `s.replace("a", "b")` без присваивания результата —
строка не меняется, и тест проверяет старое значение.

<details><summary>Проверь себя: изменяемый или нет и почему?</summary>

`frozenset` — неизменяемый (это «замороженное» множество). `bytes` — неизменяемый,
`bytearray` — изменяемый. Кортеж `(1, [2])` — сам неизменяемый, но содержит изменяемый список,
поэтому его нельзя положить в `set` (раздел 9).
</details>

### 4. `a = a + b` против `a += b`

**Простыми словами.** Кажется, что это одно и то же. Для чисел и строк так и есть, а для
списков — нет, и это любимый вопрос собеса.

- **`a + b`** всегда создаёт **новый** объект. Поэтому `a = a + b` — это «посчитать новый
  объект и переклеить на него `a`». Старый объект не меняется.
- **`a += b`** — это «изменить на месте, если умеешь». Python спрашивает у объекта: есть ли
  у тебя метод `__iadd__` (in-place add)?
  - у **списка** он есть: список расширяется на месте (как `a.extend(b)`), объект остаётся тем же;
  - у **int, str, tuple** его нет (они неизменяемы), и Python делает обычное `a = a + b` — новый объект.

```python
# Пример 1: + создаёт новый список
a = [1]
b = a                # b — второй ярлык на тот же список
a = a + [2]          # новый список [1, 2], ярлык a переклеен на него
print(a, b)          # [1, 2] [1]   — b смотрит на старый

# Пример 2: += меняет тот же список
a = [1]
b = a
a += [2]             # список расширен НА МЕСТЕ
print(a, b)          # [1, 2] [1, 2] — это всё ещё один объект

# Пример 3: += у неизменяемого — новый объект
s = "hi"
t = s
s += "!"             # у str нет __iadd__: создана новая строка "hi!"
print(s, t)          # hi! hi
```

**Где это стреляет на практике — в функциях:**

```python
def add_one(lst):
    lst += [1]        # меняет список ВЫЗЫВАЮЩЕГО кода

def add_one_safe(lst):
    lst = lst + [1]   # создаёт новый список, снаружи ничего не меняется
    return lst

data = [0]
add_one(data);       print(data)   # [0, 1]
add_one_safe(data);  print(data)   # [0, 1] — без изменений
```

**Ловушка с кортежем (разбор по шагам).** Что произойдёт?

```python
t = (1, [2])
t[1] += [3]
```

Python разворачивает `t[1] += [3]` в три действия:
1. `tmp = t[1]` — достать список `[2]`. Успешно.
2. `tmp = tmp.__iadd__([3])` — расширить список на месте. Успешно: список теперь `[2, 3]`.
3. `t[1] = tmp` — положить результат обратно в кортеж. **TypeError**: кортеж менять нельзя.

Итог: вылетает `TypeError`, но список **уже изменился**. Если поймать исключение и напечатать
`t`, увидим `(1, [2, 3])`. Ошибка есть, а изменение тоже есть — поэтому вопрос и любят.

**Бонус.** У списка `+=` принимает любой итерируемый объект, а `+` — только список:
`a = [1]; a += "xy"` даст `[1, 'x', 'y']`, а `a = a + "xy"` — `TypeError`.

<details><summary>Проверь себя: что выведет?</summary>

```python
x = (1, 2)
y = x
x += (3,)
print(x, y)
```
`(1, 2, 3) (1, 2)`. У кортежа нет `__iadd__`, поэтому `+=` создал новый кортеж и переклеил
только `x`; `y` смотрит на старый.
</details>

### 5. `is` и `==`

**Простыми словами.**
- **`==`** отвечает на вопрос «одинаковые ли **значения**?». Два разных листа бумаги с одним
  и тем же текстом — равны.
- **`is`** отвечает на вопрос «это **один и тот же** объект?». Тот же самый лист бумаги.
  `a is b` — ровно то же самое, что `id(a) == id(b)`.

```python
a = [1, 2]
b = [1, 2]
c = a
print(a == b, a is b)   # True False — значения равны, но объекты разные
print(a == c, a is c)   # True True  — c это тот же объект, что a
```

**Почему `==` можно «обмануть», а `is` нельзя.** `==` вызывает метод `__eq__` объекта, и
любой класс может переопределить его как угодно. `is` просто сравнивает `id`, его
переопределить нельзя:

```python
class AlwaysEqual:
    def __eq__(self, other):
        return True

x = AlwaysEqual()
print(x == None)    # True  — «равен» None, хотя это не None
print(x is None)    # False — правда
```

Поэтому проверка на `None` всегда пишется через `is`: `if value is None`. `None` существует
в программе в единственном экземпляре (синглтон), поэтому `is` здесь точный и быстрый.
То же для `True`, `False` и своих «маркеров» (`_MISSING = object()`).

**Кэш малых чисел и почему `is` с числами — ошибка.** CPython заранее создаёт числа от −5
до 256 и всегда отдаёт одни и те же объекты. Короткие строки, похожие на идентификаторы,
он тоже часто переиспользует (интернирование). Поэтому:

```python
a = 256; b = 256
print(a is b)       # True  — оба имени смотрят на закэшированный объект 256

a = int("1000"); b = int("1000")
print(a is b)       # False — два разных объекта 1000
print(a == b)       # True
```

Результат `is` для чисел и строк зависит от версии Python, от того, в одной строке они
созданы или нет, в скрипте или в консоли. Это деталь реализации, а не правило языка.
Python даже предупреждает: `x is 1000` выдаёт `SyntaxWarning: "is" with 'int' literal`.

**Когда использовать `is`:**
- сравнение с `None` (и `True` / `False`, хотя чаще пишут просто `if flag:`);
- в тестах — проверить, что функция вернула **тот же** объект, а не копию: `assert result is mine`;
- проверить, что две переменные не делят один изменяемый объект: `assert copy_ is not original`.

**Во всех остальных случаях — `==`.**

<details><summary>Проверь себя: что выведет?</summary>

```python
print([] is [], [] == [])
```
`False True`. Каждый `[]` создаёт новый пустой список: значения равны, объекты разные.
</details>

### 6. Копирование: псевдоним, поверхностная и глубокая копия

**Простыми словами.** Есть три уровня «копирования»:

1. **Псевдоним** (`b = a`) — не копия вовсе, а второй ярлык на тот же объект.
2. **Поверхностная копия** (shallow) — новый **внешний** контейнер, но внутри лежат ссылки
   на **те же самые** вложенные объекты. Как если переписать адреса друзей в новую записную
   книжку: книжки разные, а люди по адресам те же. Друг переехал — это видно по обеим книжкам.
3. **Глубокая копия** (deep) — копируется всё, рекурсивно, на любую глубину. Ничего общего
   с оригиналом не остаётся.

**Способы:**

| Что нужно | list | dict | любой объект |
|---|---|---|---|
| поверхностная | `a.copy()`, `list(a)`, `a[:]` | `d.copy()`, `dict(d)`, `{**d}` | `copy.copy(x)` |
| глубокая | `copy.deepcopy(a)` | `copy.deepcopy(d)` | `copy.deepcopy(x)` |

```python
import copy

src = [[1, 2], [3]]
alias = src
shallow = src.copy()
deep = copy.deepcopy(src)

src[0].append(99)        # меняем ВЛОЖЕННЫЙ список
print(alias[0])          # [1, 2, 99] — псевдоним: тот же объект
print(shallow[0])        # [1, 2, 99] — внутри общий вложенный список!
print(deep[0])           # [1, 2]     — полностью независим

src.append([4])          # меняем ВНЕШНИЙ список
print(len(shallow))      # 2 — внешние контейнеры у shallow и src разные
```

```
 src     ──▶ list [ ● , ● ] ─┬──▶ list [1, 2, 99]   ◀─┐
 shallow ──▶ list [ ● , ● ] ─┘   ...и [3] тоже общий   │ общие вложенные
                                                       │
 deep    ──▶ list [ ● , ● ] ──▶ list [1, 2]  (свои копии)
```

**Когда хватает поверхностной копии.** Когда внутри только неизменяемые объекты: список
чисел, словарь «строка → строка». Менять их на месте всё равно нельзя, поэтому общие
ссылки безопасны. Как только есть вложенные списки или словари (а JSON-тела запросов почти
всегда такие) — нужна глубокая.

**Глубокая копия умная.** `deepcopy` запоминает уже скопированные объекты (словарь `memo`).
Поэтому если объект встречается в структуре дважды, в копии он тоже будет один (общий), а
структура, ссылающаяся сама на себя, не уйдёт в бесконечную рекурсию. Цена — скорость:
`deepcopy` медленнее, большие структуры в горячем цикле копировать не стоит.

**Ловушка `[[0] * 3] * 3`.** Умножение списка повторяет **ссылки**, а не копирует объекты:

```python
grid = [[0] * 3] * 3
grid[0][0] = 1
print(grid)              # [[1, 0, 0], [1, 0, 0], [1, 0, 0]]
```

```
 grid ──▶ list [ ● , ● , ● ]
                 └───┼───┴──▶ list [1, 0, 0]     ← одна строка на троих
```

`[0] * 3` сам по себе безопасен: в нём три ссылки на один объект `0`, но `0` неизменяем, и
`row[0] = 1` не меняет ноль, а переклеивает ссылку в ячейке. Беда начинается, когда
повторяется ссылка на **изменяемый** объект. Правильно — создавать строку заново на каждой
итерации: `[[0] * 3 for _ in range(3)]`.

Та же ловушка в другой одежде: `dict.fromkeys(["a", "b"], [])` — у обоих ключей **один и тот
же** список. Правильно: `{k: [] for k in ["a", "b"]}` или `defaultdict(list)`.

<details><summary>Проверь себя: что выведет?</summary>

```python
d = dict.fromkeys(["x", "y"], [])
d["x"].append(1)
print(d)
```
`{'x': [1], 'y': [1]}` — значение у обоих ключей одно и то же.
</details>

### 7. Изменяемый аргумент по умолчанию

**Простыми словами.** `def` — это не «объявление», а обычная команда, которая выполняется,
когда Python до неё доходит. Выполняясь, она создаёт объект-функцию и **в этот момент один
раз** вычисляет значения по умолчанию. Эти значения сохраняются в функции (`f.__defaults__`)
и используются во всех вызовах, где аргумент не передали.

Доказательство, что значение по умолчанию считается при `def`, а не при вызове:

```python
def f(x=print("считаю значение по умолчанию")):
    pass
# сообщение напечаталось СРАЗУ, ещё до вызова f

f(); f()                   # больше ничего не печатается
```

Если значение по умолчанию изменяемое, все вызовы делят **один** объект:

```python
def add(item, bucket=[]):
    bucket.append(item)
    return bucket

r1 = add(1)                # bucket — список из __defaults__, он стал [1]
r2 = add(2)                # ТОТ ЖЕ список, он стал [1, 2]
print(r1, r2, r1 is r2)    # [1, 2] [1, 2] True
print(add.__defaults__)    # ([1, 2],)
```

**Правильный шаблон — `None` по умолчанию и создание объекта внутри:**

```python
def add(item, bucket=None):
    if bucket is None:     # не передали — создаём новый список на КАЖДЫЙ вызов
        bucket = []
    bucket.append(item)
    return bucket
```

Почему именно `None`: он неизменяем, и его нельзя «испортить». Если `None` — допустимое
значение аргумента, используют свой маркер: `_MISSING = object()` и `if x is _MISSING:`.

**Не только списки.** Та же проблема с `{}` и `set()`, а ещё со значениями, которые должны
быть «свежими» на каждый вызов:

```python
from datetime import datetime

def make_order(created_at=datetime.now()):   # время «замёрзло» в момент def!
    return {"created_at": created_at}

# все заказы получат одно и то же время — время загрузки модуля
```

**В dataclass** Python сам защищает от этой ошибки: `roles: list = []` выдаёт
`ValueError: mutable default <class 'list'> for field roles is not allowed`.
Правильно: `roles: list = field(default_factory=list)` — фабрика вызывается на каждый объект.

<details><summary>Проверь себя: что выведет?</summary>

```python
def f(n, seen=set()):
    seen.add(n)
    return len(seen)

f(1); f(2)
print(f(1))
```
`2`. Множество общее: после трёх вызовов в нём `{1, 2}` (повторная `1` не добавляет элемент).
</details>

### 8. Как передаются аргументы в функцию

**Простыми словами.** При вызове функции её параметры становятся новыми **ярлыками на те же
объекты**, что передал вызывающий код. Вызов `change(nums, k)` для параметров `lst, n` — это,
по сути, `lst = nums` и `n = k` внутри функции. А мы уже знаем из раздела 2: присваивание
ничего не копирует.

Отсюда два правила:
- **мутация** объекта внутри функции (`lst.append`, `d["k"] = ...`) **видна снаружи**:
  объект-то один;
- **переприсваивание** параметра (`lst = [0]`, `n += 1` для числа) снаружи **не видно**:
  переклеился только локальный ярлык.

```python
def change(lst, n):
    lst.append(1)   # мутация общего списка — снаружи увидят
    lst = [0]       # переклеили локальный ярлык lst — снаружи не увидят
    n += 1          # int неизменяем: n переклеен на 6, k снаружи остался 5

nums, k = [], 5
change(nums, k)
print(nums, k)      # [1] 5
```

```
 во время вызова, после lst.append(1):

 глобальные:  nums ──┐          k ──▶ 5
                     ├──▶ list [1]
 change():    lst  ──┘          n ──▶ 5
```

**Как это называется.** Не «по значению» и не «по ссылке»:
- если бы было **по значению** (копия, как в C), `append` внутри функции не изменил бы `nums`;
- если бы было **по ссылке** (как `&` в C++), `lst = [0]` изменил бы `nums` снаружи.

Ни то, ни другое не верно. Правильный термин — **передача по ссылке на объект** (pass by
object reference, call by sharing).

**Хороший тон.** Функция, которая меняет переданный объект, должна явно об этом говорить
(как `list.sort()`, которая возвращает `None`). Иначе — работать с копией и возвращать новый
объект (как `sorted()`). Хелперы тестового фреймворка лучше писать во втором стиле: меньше
сюрпризов.

<details><summary>Проверь себя: что выведет?</summary>

```python
def f(d):
    d["x"] = 1
    d = {}
    d["y"] = 2

data = {}
f(data)
print(data)
```
`{'x': 1}`. Первая строка — мутация общего словаря, дальше `d` переклеен на новый словарь,
и `y` попадает уже в него.
</details>

### 9. Хешируемость

**Простыми словами.** Словарь и множество находят элемент мгновенно, не перебирая всё
подряд. Для этого у ключа вычисляется **хеш** — число, полученное из значения (`hash(x)`).
По хешу словарь сразу понимает, в какую «ячейку» смотреть. Как в библиотеке: книги разложены
по первой букве фамилии автора, и ты идёшь сразу к нужной полке.

Чтобы это работало, хеш должен соблюдать два правила:
1. **Равные объекты имеют равный хеш:** если `a == b`, то `hash(a) == hash(b)`.
2. **Хеш не меняется**, пока объект лежит в словаре.

**Почему список не может быть ключом.** Представь, что можно: положили ключ `[1, 2]`,
словарь разложил его по хешу «на полку 7». Потом кто-то сделал `key.append(3)` — значение
изменилось, хеш тоже должен измениться, и теперь словарь ищет этот ключ на другой полке.
Ключ «потерялся». Поэтому Python запрещает это сразу: изменяемые встроенные типы
нехешируемы.

```python
d = {}
d[(1, 2)] = "ok"           # кортеж из чисел — хешируемый
d[[1, 2]] = "x"            # TypeError: unhashable type: 'list'
d[(1, [2])] = "x"          # TypeError: unhashable type: 'list' — внутри кортежа список
s = {frozenset({1, 2})}    # frozenset можно положить в set, обычный set — нет
```

Кортеж хешируем, только если **всё внутри** хешируемо: его хеш считается из хешей элементов.

**Почему `{1: "a", 1.0: "b", True: "c"}` — это `{1: 'c'}`.** `1 == 1.0 == True`, и хеши у них
одинаковые (`bool` — подкласс `int`, `True` ведёт себя как `1`). Для словаря это один и тот же
ключ. При повторной записи ключ остаётся первым (`1`), а значение — последним (`'c'`).

**Свои классы.** По умолчанию объекты твоего класса хешируются по `id` (каждый объект равен
только сам себе). Если переопределить `__eq__` и не определить `__hash__`, Python сделает
объект нехешируемым, чтобы не нарушить правило 1. Подробно — в уроке C9.

<details><summary>Проверь себя: какие строки упадут?</summary>

```python
{(1, "a"): 1}
{(1, ["a"]): 1}
{frozenset([1]): 1}
{{1}: 1}
```
Упадут вторая (`list` внутри кортежа) и четвёртая (`set` нехешируем).
</details>

### 10. Где это ломает автотесты

**Общий шаблон данных и поверхностная копия.**

```python
BASE_USER = {"email": "a@b.c", "roles": ["user"]}

def test_admin():
    user = BASE_USER.copy()           # поверхностная: roles — общий список!
    user["roles"].append("admin")     # испортили BASE_USER для всех

def test_regular_user():
    assert BASE_USER["roles"] == ["user"]   # падает, если test_admin шёл раньше
```

Фикс: `copy.deepcopy(BASE_USER)` или фабрика `make_user()`, которая каждый раз строит новый dict.

**Фикстура с широким scope отдаёт изменяемый объект.**

```python
@pytest.fixture(scope="session")
def default_order():
    return {"symbol": "BTC/USDT", "qty": "1"}
# один объект на весь прогон: тест, который сделал default_order["qty"] = "0",
# сломает все тесты после себя
```

Фикс: `scope="function"` для изменяемых данных или отдавать копию.

**Мок хранит ссылку, а не снимок.**

```python
from unittest.mock import Mock

client = Mock()
payload = {"qty": 1}
client.post(payload)
payload["qty"] = 5
print(client.post.call_args)   # call({'qty': 5}) — «история» изменилась задним числом
```

Проверку `assert_called_with` делай до того, как меняешь объект, или передавай копию
(задача t10 — свой записыватель вызовов со снимками).

**Хелпер со значением по умолчанию.** `def create_user(roles=[])` или
`def make_order(ts=datetime.now())` — данные «протекают» между тестами или время замерзает.

**Как распознать.** Тест проходит сам по себе (`pytest -k test_x`), но падает в общем прогоне
или при другом порядке тестов. Первым делом ищи общий изменяемый объект: модульную
константу-словарь, фикстуру с `scope="session"` или `"module"`, значение по умолчанию.

### 11. Шпаргалка

1. Переменная — ярлык на объект. Присваивание ничего не копирует.
2. Различай мутацию объекта и переприсваивание имени.
3. Неизменяемые: числа, `str`, `bytes`, `tuple`, `frozenset`, `None`. Их «изменение» создаёт новый объект.
4. Методы, меняющие объект на месте, возвращают `None` (`sort`, `append`, `update`).
5. `+` всегда создаёт новый объект; `+=` у списка меняет тот же объект.
6. `==` — равенство значений, `is` — один и тот же объект. `is` — только для `None` и синглтонов.
7. `copy()`, `[:]`, `dict(d)` — поверхностные копии. Для вложенных структур — `copy.deepcopy`.
8. `[[x] * n] * m` и `dict.fromkeys(keys, [])` делят один вложенный объект.
9. Значения по умолчанию вычисляются один раз при `def`. Для изменяемых — `None` и создание внутри.
10. Аргументы передаются по ссылке на объект: мутация видна снаружи, переприсваивание — нет.
11. Ключи dict и элементы set должны быть хешируемыми; кортеж хешируем, если всё внутри хешируемо.

### Собес

- **Чем изменяемые типы отличаются от неизменяемых? Примеры.**
  Изменяемый объект можно поменять на месте, не создавая новый: `list`, `dict`, `set`. Все имена,
  которые на него ссылаются, видят изменение. Неизменяемый объект поменять нельзя: `int`, `str`,
  `tuple`, `frozenset`; любая «модификация» возвращает новый объект. Практическое следствие:
  только неизменяемые объекты могут быть ключами словаря, и их безопасно передавать куда угодно.

- **Чем `is` отличается от `==`? Почему `x is None`?**
  `==` сравнивает значения через метод `__eq__`, который класс может переопределить. `is`
  проверяет, что это один и тот же объект (одинаковый `id`), и переопределить его нельзя.
  `None` — синглтон, поэтому `is None` точен и не зависит от чужого `__eq__`. Для чисел и
  строк `is` не используют: совпадения из-за кэша CPython — деталь реализации.

- **Что такое поверхностная и глубокая копия? Когда это важно?**
  Поверхностная создаёт новый внешний контейнер, но вложенные объекты остаются общими с
  оригиналом. Глубокая (`copy.deepcopy`) рекурсивно копирует всё и корректно обрабатывает
  циклические и общие ссылки. Важно для вложенных изменяемых структур: например, шаблон
  JSON-тела запроса в тестах надо копировать глубоко, иначе один тест испортит его другим.

- **Что не так с `def f(x=[])`?**
  Значение по умолчанию вычисляется один раз, когда выполняется `def`, и хранится в
  `f.__defaults__`. Все вызовы без аргумента получают один и тот же список, и он накапливает
  данные. Решение: `x=None` и внутри `if x is None: x = []`. В dataclass — `field(default_factory=list)`.

- **Python передаёт аргументы по ссылке или по значению?**
  Ни так, ни так: по ссылке на объект (call by sharing). Параметр становится ещё одним именем
  того же объекта. Поэтому изменение изменяемого объекта внутри функции видно снаружи, а
  переприсваивание параметра — нет.

- **Почему список не может быть ключом словаря, а кортеж может?**
  Словарь находит ключ по хешу, а хеш должен оставаться неизменным, пока ключ в словаре.
  Список изменяем: изменился бы его хеш, и ключ «потерялся» бы. Поэтому `list` нехешируем.
  Кортеж неизменяем и хешируем, но только если все его элементы хешируемы: `(1, [2])` ключом
  быть не может.

- **Что выведет `grid = [[0] * 3] * 3; grid[0][0] = 1; print(grid)`? Как правильно?**
  `[[1, 0, 0], [1, 0, 0], [1, 0, 0]]`: внешнее умножение повторило ссылку на один внутренний
  список. Правильно: `[[0] * 3 for _ in range(3)]`, где каждая строка создаётся заново.

- **Почему для списка `a = a + b` и `a += b` ведут себя по-разному?**
  `+` всегда создаёт новый список, и `a` переклеивается на него. `+=` вызывает `__iadd__`
  и расширяет существующий список на месте, поэтому изменение видят все ссылки на него.
  У неизменяемых типов `__iadd__` нет, и `+=` работает как `a = a + b`.

- **Что будет при `t = (1, [2]); t[1] += [3]`?**
  Вылетит `TypeError`, но список внутри кортежа уже изменится: `t` станет `(1, [2, 3])`.
  Сначала выполняется `__iadd__` у списка (успешно), затем присваивание в кортеж (ошибка).

- **Где эта тема встречается в автотестах?**
  Общие тестовые данные, которые один тест мутирует; фикстуры с `scope="session"`, отдающие
  изменяемые объекты; моки, которые хранят ссылку на аргумент вместо снимка; хелперы с
  изменяемым значением по умолчанию или `datetime.now()` по умолчанию. Защита — глубокие
  копии, фабрики данных, `None` по умолчанию и узкий scope для изменяемых фикстур.
