# A7 · Бинарный поиск

**Смысл темы.** Если данные **отсортированы** (или ответ «монотонный»: до какого-то места «нет»,
после — «да»), то искать можно делением пополам: посмотрели в середину — и выбросили половину,
где ответа точно нет. Из миллиона элементов хватает 20 шагов: O(log n) вместо O(n). На собесе
главное — не сам алгоритм, а **границы**: `lo <= hi` или `lo < hi`, `mid + 1` или `mid`. Ошибка
на единицу даёт бесконечный цикл или пропуск ответа.

**Сигналы в условии:** «отсортированный массив», «найти позицию / первый / последний», «за O(log n)»,
«минимальное значение, при котором …» (поиск по ответу), «повёрнутый массив».

---

### 1. Классический шаблон: найти элемент

```python
def binary_search(nums, target):
    lo, hi = 0, len(nums) - 1           # ищем в отрезке [lo, hi] включительно
    while lo <= hi:                     # пока отрезок не пуст
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            lo = mid + 1                # mid и всё левее — не ответ
        else:
            hi = mid - 1                # mid и всё правее — не ответ
    return -1
```

```
nums = [1, 3, 5, 7, 9, 11], target = 9

lo=0 hi=5 mid=2 → 5 < 9  → lo=3
lo=3 hi=5 mid=4 → 9 == 9 → return 4
```

- **Инвариант:** если target есть, он лежит в `[lo, hi]`. Каждый шаг сохраняет это и сужает отрезок.
- **`lo <= hi`** — отрезок из одного элемента (`lo == hi`) тоже нужно проверить.
- **`mid ± 1`** — середину уже проверили, её исключаем; иначе возможен бесконечный цикл.
- **Переполнение `(lo + hi)` в Python не страшно** (int без предела), но в Java/C пишут
  `lo + (hi - lo) // 2` — об этом могут спросить.

### 2. Шаблон «первый, для которого условие истинно»

Самый полезный вариант: ищем **границу** — первый индекс, где `condition(i)` становится True
(и дальше остаётся True).

```python
def first_true(lo, hi, condition):      # ответ в [lo, hi]; hi — «точно True» или граница
    while lo < hi:
        mid = (lo + hi) // 2
        if condition(mid):
            hi = mid                    # mid может быть ответом — не выкидываем
        else:
            lo = mid + 1                # mid точно не ответ
    return lo

# первая позиция, куда можно вставить target (lower bound)
pos = first_true(0, len(nums), lambda i: nums[i] >= target)   # i == len(nums) не вызывается
```

- **`lo < hi`** и **`hi = mid`** (без −1): цикл кончается, когда `lo == hi` — это и есть ответ.
- **Так решаются:** позиция вставки, первое/последнее вхождение, корень, поиск по ответу.
- **`bisect` из стандартной библиотеки:** `bisect_left(nums, x)` — первая позиция `>= x`,
  `bisect_right(nums, x)` — первая `> x`. Количество вхождений x = `bisect_right - bisect_left`.

### 3. Поиск по ответу

Когда ответ — число из диапазона, и проверка «подходит ли значение v» монотонна (если v подходит,
то и все большие подходят), ищем минимальное подходящее бинпоиском **по значениям**, а не по массиву.

```python
import math

def min_speed(piles, hours):            # Koko ест бананы: минимальная скорость, чтобы успеть
    def enough(speed):
        return sum(math.ceil(p / speed) for p in piles) <= hours

    lo, hi = 1, max(piles)              # скорость max(piles) точно хватает
    while lo < hi:
        mid = (lo + hi) // 2
        if enough(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo
```

- **Сложность:** O(n · log(max)) — log шагов, на каждом проверка за O(n).
- **Где ещё:** минимальная вместимость корабля за D дней, минимальный размер пачки, при котором
  время обработки укладывается в SLA, `sqrt(x)` (наибольшее k, где k*k <= x).

### 4. Повёрнутый массив

`[4, 5, 6, 7, 0, 1, 2]` — отсортированный массив, сдвинутый по кругу. В середине одна из половин
**всегда отсортирована** — по ней и решаем, куда идти.

```python
def search_rotated(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[lo] <= nums[mid]:                    # левая половина отсортирована
            if nums[lo] <= target < nums[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:                                         # правая половина отсортирована
            if nums[mid] < target <= nums[hi]:
                lo = mid + 1
            else:
                hi = mid - 1
    return -1
```

### 5. Бинарный поиск в AQA

- **`git bisect`** — бинарный поиск коммита, который сломал тест: из 1000 коммитов — 10 прогонов.
- **Поиск порога нагрузки:** при каком RPS латентность вылезает за SLA — бинпоиск по RPS.
- **Минимальный воспроизводящий пример:** делить входные данные пополам, пока баг воспроизводится.
- **Пагинация по времени/курсору** — поиск первой страницы, где события новее заданного момента.

---

**Частые ошибки.**
- Бинпоиск по неотсортированным данным.
- `while lo < hi` с `hi = mid - 1` (или `lo <= hi` с `hi = mid`) — смешали шаблоны: бесконечный
  цикл или пропуск.
- `lo = mid` без `+1` при `mid = (lo + hi) // 2` — зацикливание на двух элементах.
- Не обработан пустой массив / target за пределами.
- В поиске по ответу неверные границы `lo`, `hi` — ответ вне диапазона.

---

### Собес

- **Когда применим бинарный поиск?** Когда данные отсортированы или условие монотонно: до какой-то
  точки «нет», после — «да». Каждый шаг отбрасывает половину — O(log n).
- **`lo <= hi` или `lo < hi`?** Если ищем конкретный элемент в отрезке `[lo, hi]` — `lo <= hi` и
  `mid ± 1`. Если ищем границу «первый True» — `lo < hi`, при True `hi = mid`, иначе `lo = mid + 1`,
  ответ — `lo`.
- **Что такое поиск по ответу?** Бинпоиск по диапазону возможных значений ответа с монотонной
  проверкой «значение подходит». Например, минимальная скорость, при которой успеваем за H часов.
- **Где бинарный поиск в работе тестировщика?** `git bisect` для поиска сломавшего коммита, поиск
  порога нагрузки, сужение входных данных до минимального воспроизведения.
