## 1. Что такое хеш-таблица и почему она быстрая

Представь два способа хранить вещи:

- **list — стопка бумаг.** Чтобы найти нужный лист, перебираешь по одному. 1000 листов — до 1000 проверок. Это **O(n)**.
- **set / dict — шкаф с подписанными ящиками.** По имени вещи сразу понятно, в каком она ящике. Открыл ящик, проверил. Одна проверка при любом размере шкафа. Это **O(1)**.

Как Python узнаёт номер ящика: вызывает `hash(x)`. Это функция, которая превращает значение в число. По этому числу и выбирается ячейка.

```python
hash("eat")   # какое-то большое число, всегда одинаковое для "eat" в этом запуске
hash(42)      # 42
```

Для одинаковых значений `hash` всегда одинаковый. Поэтому `"eat" in s` не перебирает всё, а сразу смотрит в одну ячейку.

**Цена скорости — память.** Множество или словарь из n элементов занимает O(n) памяти. На собесе это называют «обменял память на время».

## 2. set — множество

Хранит только **уникальные** значения, **без порядка**, без индексов.

```python
s = set([3, 1, 3, 2, 1])   # {1, 2, 3}  — дубли исчезли
s.add(5)                   # добавить
s.discard(7)               # удалить, если есть (remove упадёт, если нет)
5 in s                     # True, O(1)
len(s)                     # 4
```

| Операция | Запись | Результат для `a={1,2,3}`, `b={2,3,4}` |
|---|---|---|
| пересечение | `a & b` | `{2, 3}` |
| объединение | `a \| b` | `{1, 2, 3, 4}` |
| разность | `a - b` | `{1}` |
| симм. разность | `a ^ b` | `{1, 4}` |

**Когда брать set:** «есть ли повтор», «видел ли раньше», «убрать дубли», «общие элементы».

Ловушки:
- `{}` — это пустой **dict**, а не set. Пустое множество — `set()`.
- `s[0]` — ошибка: у set нет индексов.
- Порядок элементов в set не гарантирован. Не сравнивай вывод set со списком.

## 3. dict — словарь

Хранит пары **ключ → значение**. Ключи уникальные, поиск по ключу O(1).

```python
ages = {"ann": 30, "bob": 25}
ages["kate"] = 41        # добавить или перезаписать
ages["ann"]              # 30
ages["zed"]              # KeyError! ключа нет
ages.get("zed")          # None — без ошибки
ages.get("zed", 0)       # 0 — своё значение по умолчанию
"bob" in ages            # True — in проверяет КЛЮЧИ, не значения
del ages["bob"]          # удалить
```

| Обход | Что даёт |
|---|---|
| `for k in d` | ключи |
| `for v in d.values()` | значения |
| `for k, v in d.items()` | пары |

С Python 3.7 dict **помнит порядок вставки**. А set порядок не помнит.

**Когда брать dict:** нужно не только «было ли», а ещё что-то про это: индекс, количество, группу.

## 4. Подсчёт: три способа (на собесе спросят все)

Задача: сколько раз встречается каждая буква в `"banana"`.

```python
# 1. Руками через get — понимать обязательно
counts = {}
for ch in "banana":
    counts[ch] = counts.get(ch, 0) + 1
# {'b': 1, 'a': 3, 'n': 2}

# 2. defaultdict(int) — отсутствующий ключ сразу равен 0
from collections import defaultdict
counts = defaultdict(int)
for ch in "banana":
    counts[ch] += 1

# 3. Counter — одной строкой
from collections import Counter
counts = Counter("banana")       # Counter({'a': 3, 'n': 2, 'b': 1})
counts["z"]                      # 0 — не падает
counts.most_common(2)            # [('a', 3), ('n', 2)]
```

Почему в первом способе `get(ch, 0)`: при первой встрече буквы её ещё нет в словаре, `counts[ch]` упал бы с KeyError.

Полезное про Counter:
- `Counter("ab") == Counter("ba")` → `True`. Так проверяют анаграммы.
- `Counter(a) & Counter(b)` — минимум количеств (общие элементы с повторами).
- `Counter(a) - Counter(b)` — чего не хватает (отрицательные отбрасываются).

## 5. defaultdict(list) — группировка

```python
by_letter = defaultdict(list)
for w in ["apple", "avocado", "banana"]:
    by_letter[w[0]].append(w)
# {'a': ['apple', 'avocado'], 'b': ['banana']}
```

Без defaultdict пришлось бы писать `if key not in d: d[key] = []` перед каждым append.
В автотестах так группируют, например, ответы API по статусу или логи по `request_id`.

## 6. Что может быть ключом

Ключ (и элемент set) должен быть **hashable**, то есть неизменяемым:

| Можно | Нельзя |
|---|---|
| `int`, `float`, `str`, `bool` | `list` |
| `tuple` (если внутри тоже hashable) | `dict` |
| `frozenset` | `set` |

Почему: если бы список был ключом и его потом изменили, `hash` изменился бы, и словарь «потерял» бы ключ.

```python
d[(1, 2)] = "ok"       # tuple — можно
d[[1, 2]] = "nope"     # TypeError: unhashable type: 'list'
```

Отсюда приём для анаграмм: ключ — `"".join(sorted(word))` или `tuple(sorted(word))`, но не `sorted(word)`, это список.

## 7. Паттерн «уже видел» (seen)

Идём по данным один раз. Для каждого элемента спрашиваем: «такой уже был?» Прошлое храним в set.

```python
seen = set()
for x in items:
    if x in seen:
        ...          # нашли повтор
    seen.add(x)
```

Задачи: есть ли дубль, первый повторяющийся элемент, уникальные в порядке появления.

## 8. Паттерн «ищу пару» (complement) — Two Sum

Нужно два числа с суммой `target`. Для текущего `x` пара — это `need = target - x`.
Вместо второго цикла спрашиваем словарь: «need уже встречался?»

```python
seen = {}                     # число -> индекс
for i, x in enumerate(nums):
    need = target - x
    if need in seen:          # 1) СНАЧАЛА спросить
        return [seen[need], i]
    seen[x] = i               # 2) ПОТОМ записать
```

Почему порядок важен: на `[3, 3], target=6`, если сначала записать `3`, на индексе 0 число найдёт само себя и вернёт `[0, 0]`.
Почему dict, а не set: нужен индекс пары, а set его не хранит.

## 9. Паттерн «ключ группы»

Придумай ключ, который одинаковый у всех элементов одной группы, и раскладывай по `defaultdict(list)`.
- Анаграммы: ключ — отсортированные буквы.
- Слова по длине: ключ — `len(word)`.
- Логи: ключ — `request_id`.

## 10. Сложность — таблица

| Операция | list | set / dict |
|---|---|---|
| `x in ...` | O(n) | **O(1)** |
| добавить | O(1) в конец | O(1) |
| удалить по значению / ключу | O(n) | O(1) |
| по индексу `[i]` | O(1) | нет (у dict — по ключу O(1)) |
| `Counter(s)` | — | O(n) |
| `most_common(k)` | — | O(n log k) |

O(1) у dict/set — **в среднем**. В худшем случае (все ключи попали в одну ячейку, коллизии) O(n), но в реальной жизни это почти не случается.

## 11. Частые ошибки

1. `x in list` внутри цикла → O(n²). Лечится set'ом.
2. `d[key] += 1` в обычном dict при первой встрече → KeyError. Нужен `get(key, 0)`, `defaultdict(int)` или `Counter`.
3. `{}` вместо `set()` для пустого множества.
4. list как ключ → `unhashable type: 'list'`.
5. В Two Sum записать раньше, чем проверить → число находит само себя.
6. Надеяться на порядок в set.
7. `set(a) & set(b)` там, где важны повторы: `[1, 1]` и `[1, 1]` дадут `{1}`, а надо `[1, 1]`. Нужен Counter.

## 12. Собес: готовые ответы

**Почему поиск в dict O(1)?**
По ключу считается `hash`, по нему сразу вычисляется ячейка. Перебирать элементы не нужно.

**Что такое коллизия?**
Два разных ключа попали в одну ячейку. Python тогда ищет следующую свободную ячейку (открытая адресация). Если коллизий много, поиск деградирует до O(n).

**Почему list не может быть ключом?**
Список изменяемый: после изменения у него был бы другой hash, и словарь не нашёл бы ключ. Ключи должны быть hashable, то есть неизменяемые: str, int, tuple.

**set или list для проверки «есть ли элемент»?**
set: O(1) против O(n). Если проверок много, разница в тысячи раз.

**Чем Counter отличается от dict?**
Это подкласс dict для подсчёта. Отсутствующий ключ даёт 0, а не KeyError. Есть `most_common`, сложение и пересечение счётчиков.

**Two Sum — объясни решение.**
В лоб — два цикла, O(n²). Лучше: один проход, для каждого x считаю `need = target - x` и проверяю, был ли need в словаре «число → индекс». Если был — ответ, иначе кладу x. Время O(n), память O(n).

**Где это в автотестах?**
Сравнить два ответа API без учёта порядка — `Counter(a) == Counter(b)`. Найти дубли id в выдаче — set. Сгруппировать логи по `request_id` — `defaultdict(list)`. Кеш токенов по пользователю — dict.
