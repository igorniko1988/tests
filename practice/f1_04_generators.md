## Зачем это QA

- `yield` в **фикстурах** pytest — подготовка до теста и уборка после.
- `with` — открыть и гарантированно закрыть: файл, браузер (`with sync_playwright()`),
  сессию, ожидание ответа (`with page.expect_response(...)`).
- Генераторы — перебор страниц API, больших файлов и тестовых данных без загрузки всего в память.

## 1. Итерируемое и перебор

`for` умеет перебирать списки, строки, словари, файлы — всё, что «итерируемо».
Внутри `for` берёт у объекта следующий элемент, пока элементы не закончатся.

## 2. Генератор — функция с `yield`

```python
def countdown(n):
    while n > 0:
        yield n          # отдать значение и ЗАМЕРЕТЬ здесь
        n -= 1


for x in countdown(3):
    print(x)             # 3, 2, 1
```

- `return` возвращает значение **один раз** и функция заканчивается.
- `yield` **отдаёт** значение и **ставит функцию на паузу**. Следующий запрос — продолжает с того же места.

```python
gen = countdown(2)
next(gen)    # 2  — дошли до первого yield
next(gen)    # 1  — продолжили, дошли до второго
next(gen)    # StopIteration — функция закончилась
```

Вызов `countdown(3)` **ничего не выполняет** — только создаёт генератор. Код идёт по кусочкам, при каждом `next`.

## 3. Ленивость: зачем генератор вместо списка

```python
numbers_list = [x * 2 for x in range(10_000_000)]   # сразу 10 млн чисел в памяти
numbers_gen = (x * 2 for x in range(10_000_000))    # почти ничего: считает по одному
```

Генератор считает значения **по требованию**. Подходит для больших данных и для бесконечных
последовательностей. Минус — пройти можно **один раз**: второй `for` по тому же генератору ничего не даст.

`(x * 2 for x in ...)` в круглых скобках — **генераторное выражение**, ленивая версия list comprehension.

## 4. Генератор в тестах: перебор страниц API

```python
def all_orders(client):
    cursor = None
    while True:
        response = client.get("/orders", params={"cursor": cursor})
        yield from response.json()                  # отдать каждый ордер страницы по одному
        cursor = response.headers.get("X-Next-Cursor")
        if cursor is None:
            return                                  # страниц больше нет — генератор закончился


for order in all_orders(client):
    ...                                             # страницы подгружаются по мере перебора
```

`yield from список` — отдать все элементы по очереди (то же, что `for x in список: yield x`).

## 5. `yield` в фикстурах pytest

```python
@pytest.fixture
def user():
    created = create_user()     # ДО теста: подготовка
    yield created               # отдать тесту и ЗАМЕРЕТЬ, пока идёт тест
    delete_user(created)        # ПОСЛЕ теста: уборка (даже если тест упал)
```

Это тот же генератор: pytest вызывает его до `yield`, отдаёт значение тесту, а после теста
«досылает» генератор до конца — и выполняется уборка.

## 6. Контекстный менеджер и `with`

```python
with open("orders.csv") as file:
    data = file.read()
# здесь файл уже закрыт — даже если внутри with была ошибка
```

`with` гарантирует: **вход** (открыть) и **выход** (закрыть) выполнятся всегда.

### Свой контекстный менеджер — класс

```python
import time


class Timer:
    def __enter__(self):                    # вход в with
        self.start = time.perf_counter()
        return self                          # это попадёт в переменную после as

    def __exit__(self, exc_type, exc, tb):   # выход из with — ВСЕГДА
        self.elapsed = time.perf_counter() - self.start
        print(f"заняло {self.elapsed:.3f} с")
        return False                         # False — ошибку не глушить, пробросить дальше


with Timer() as t:
    time.sleep(0.2)
```

- `__enter__` — что сделать при входе; что он вернёт — то будет в `as t`.
- `__exit__` — что сделать при выходе. Вызывается **и при ошибке**: тогда в `exc_type`, `exc`, `tb`
  лежат тип, сама ошибка и трейсбек. Если вернуть `True`, ошибка будет **проглочена** — почти никогда так не делают.

### Свой контекстный менеджер — через генератор

То же самое короче, с декоратором `@contextmanager`:

```python
from contextlib import contextmanager


@contextmanager
def timer():
    start = time.perf_counter()          # вход
    try:
        yield                            # здесь выполняется тело with
    finally:
        print(f"заняло {time.perf_counter() - start:.3f} с")   # выход — всегда


with timer():
    time.sleep(0.2)
```

`try/finally` нужен, чтобы выход выполнился **даже при ошибке** внутри `with`.
Посмотри: это та же форма, что у фикстуры с `yield`.

## 7. Где `with` в Playwright

```python
with sync_playwright() as p:                         # запустить и гарантированно остановить
    browser = p.chromium.launch()

with page.expect_response("**/orders") as info:      # начать ждать ответ ДО клика
    page.get_by_test_id("place-order-button").click()
response = info.value
```

## Шпаргалка

| Что | Как | Зачем |
|---|---|---|
| генератор | функция с `yield` | значения по одному, лениво |
| генераторное выражение | `(x for x in ...)` | ленивый comprehension |
| `next(gen)` | следующий элемент | ручной перебор |
| `yield from seq` | отдать все элементы | вложенный перебор |
| фикстура с `yield` | до → `yield` → после | подготовка и уборка |
| `with` | `__enter__` / `__exit__` | гарантированный вход и выход |
| `@contextmanager` | генератор + `try/finally` | короткий контекстный менеджер |
