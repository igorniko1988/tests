# F2. Урок 4 — собес: «протестируй поле / форму / эндпоинт» без кода

Задания: `practice/f2_04_interview_answers.md`.

## Что проверяют этим вопросом

Не количество проверок, а **структуру мышления**. Плохой ответ — 30 случайных проверок подряд.
Хороший — сначала вопросы, потом проверки по группам, потом приоритеты.

## Схема ответа (запомни)

1. **Уточни требования** (1–2 минуты). Что это, для кого, какие ограничения, что уже покрыто.
2. **Позитивные** проверки — основной сценарий работает.
3. **Негативные** — классы эквивалентности и границы для каждого поля.
4. **Логика и состояния** — комбинации (таблица решений), статусы, повторные действия.
5. **Нефункциональные** — безопасность, производительность, UI/UX, доступность, локализация, совместимость.
6. **Приоритеты и автоматизация** — что в smoke, что на каком уровне пирамиды.

Говори вслух **группами**: «теперь граничные значения для пароля...».

## Пример: «Протестируй форму логина»

**Вопросы:** формат логина (email/телефон)? Ограничения пароля? Блокировка после N попыток?
«Запомнить меня»? 2FA? Куда редирект после входа? Есть ли SSO?

**Позитивные:** верные данные → вход и редирект; email в другом регистре; Enter вместо кнопки.

**Негативные:** неверный пароль; несуществующий email; пустые поля; пробелы в начале/конце;
невалидный email; очень длинные значения; спецсимволы и юникод.

**Логика:** блокировка после N неудач и разблокировка; сессия: logout, истечение токена,
вход в двух вкладках; кнопка «назад» после выхода.

**Безопасность:** одинаковое сообщение для «нет email» и «неверный пароль» (не раскрывать, есть ли пользователь);
пароль замаскирован и не уходит в URL/логи; HTTPS; SQL-инъекция и XSS в полях; brute-force / rate limit.

**UI/UX:** фокус, Tab-порядок, тексты ошибок, состояние кнопки во время запроса (двойной клик),
мобильная вёрстка, автозаполнение браузера.

**Автоматизация:** валидация — API-тесты; успешный вход и ошибки — пара UI-тестов; вход — в smoke.

## Пример: «Протестируй эндпоинт POST /orders»

**Вопросы:** обязательные поля и их форматы? Какие коды ответов? Идемпотентность? Лимиты? Кто может вызывать?

| Группа | Проверки |
|---|---|
| позитив | 201, тело ответа по схеме, ордер виден в GET, баланс заблокирован |
| авторизация | без токена 401, просроченный 401, чужой ресурс 404/403 |
| валидация | каждое поле: нет / null / пустое / неверный тип / границы / лишние поля |
| бизнес-логика | недостаточно средств 400 и баланс не изменился; BUY блокирует quote, SELL — base |
| идемпотентность | повтор с тем же ключом → тот же ответ, ордер один |
| конкурентность | 10 параллельных ордеров на весь баланс — создастся не больше, чем хватает денег |
| контракт | Content-Type, формат сумм строкой, поля не исчезли |
| нефункционал | время ответа, поведение при 503 (retry), rate limit |
| данные | запись в БД соответствует ответу |

## Классика: «Протестируй карандаш / лифт / чашку»

Та же схема: уточнить (для кого, какие требования) → функциональные → граничные/негативные →
нефункциональные (прочность, безопасность, удобство, эргономика) → приоритеты.
Проверяют не знание предмета, а **подход**.

## Вопросы собеседования

1. С чего начнёшь, если просят протестировать что-то без требований?
2. Протестируй поле «сумма перевода».
3. Протестируй форму регистрации.
4. Протестируй эндпоинт `GET /orders?status=NEW&limit=20`.
5. Протестируй лифт.
