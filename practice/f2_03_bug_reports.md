## 1. Хороший баг-репорт

Цель — разработчик **воспроизводит баг с первого раза**, не задавая вопросов.

| Поле | Пример |
|---|---|
| Заголовок | Отмена PARTIALLY_FILLED ордера возвращает в available весь locked, а не остаток |
| Окружение | stage :8081, сборка 1.2.3, Chrome 129, macOS |
| Предусловия | пользователь с USDT = 1000 |
| Шаги | 1. BUY ETH-USDT price=100 qty=2. 2. Второй пользователь SELL price=100 qty=1. 3. Дождаться PARTIALLY_FILLED. 4. Отменить ордер |
| Фактический результат | USDT available = 1000, locked = 0 |
| Ожидаемый результат | USDT available = 900, locked = 0 (100 потрачено на исполненную часть) |
| Severity / Priority | Critical / P1 |
| Вложения | запрос и ответ (curl), request id, скриншот, лог сервиса |

Заголовок по формуле **«что — где — при каком условии»**. Плохо: «баланс сломался».

Для API-бага лучшее вложение — **готовая curl-команда** и тело ответа. Для UI — видео или trace Playwright.
Всегда — **request id / время**, чтобы найти запись в логах.

Один баг — один репорт. Прежде чем заводить — поищи дубли.

## 2. Severity и Priority

**Severity** — насколько баг **ломает систему** (технически). Ставит QA.
**Priority** — насколько **срочно чинить** (бизнес). Решает PM / тимлид.

| Severity | Пример |
|---|---|
| Blocker | не работает логин — тестировать дальше нельзя |
| Critical | неверное списание денег |
| Major | не работает фильтр ордеров |
| Minor | неверный текст ошибки |
| Trivial | опечатка, сдвиг на 1px |

Классические вопросы — они **не всегда совпадают**:
- **high severity, low priority**: падение при очень редкой комбинации, которую почти никто не делает;
- **low severity, high priority**: опечатка в названии компании на главной странице перед запуском рекламы.

## 3. Жизненный цикл бага

```text
New → Open/In Progress → Fixed/Resolved → (QA проверяет) → Closed
                                      └─ не исправлено → Reopened
Также: Rejected (не баг), Duplicate, Cannot Reproduce, Won't Fix
```

## 4. Jira

- **Issue types**: Epic → Story/Task → Sub-task, отдельно **Bug**.
- Поля: assignee, reporter, priority, labels, components, fix version, sprint.
- Связи: *blocks*, *relates to*, *duplicates* — баг связывают со story, в которой нашли.
- **JQL** — язык поиска, на собесе могут спросить:

```text
project = EX AND type = Bug AND status != Closed AND priority in (Highest, High) ORDER BY created DESC
```

## 5. TestRail / Xray — управление тестами

Где хранятся тест-кейсы и результаты прогонов.

| Понятие | Что это |
|---|---|
| test case | кейс с шагами, в секциях/сьютах |
| test run | прогон набора кейсов на конкретной сборке |
| test plan | несколько runs (разные окружения/браузеры) |
| milestone | релиз |

**Xray** — то же внутри Jira (кейсы — это issue типа Test). **TestRail** — отдельный сервис.

Связь с автотестами: у теста в коде есть ID кейса (маркер `@pytest.mark.case("C123")` или в Allure
`@allure.testcase`), CI после прогона отправляет результаты в TestRail/Xray через API.
Тогда менеджер видит в одном месте и ручные, и авто-результаты.
