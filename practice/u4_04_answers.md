# U4.4 — ответы

## Задача 1. Деньги

**Почему `Decimal(0.1) != Decimal("0.1")`.** `0.1` без кавычек — float, он хранится в двоичном виде,
а 0.1 в двоичной системе — бесконечная дробь, её обрезают. `Decimal(0.1)` честно переносит это неточное
значение: `0.1000000000000000055511151231257827…`. `Decimal("0.1")` читает текст — ровно 0.1.
Поэтому `to_decimal` делает `Decimal(str(value))`, а деньги создаются только из строк.

**Где тесты утилит.** В `tests/unit/`, а не в `tests/ui/`: в `tests/ui/conftest.py` autouse-фикстура
таймаута просит `page`, и любой тест в этой папке поднимал бы браузер. Область autouse = папка её conftest.

## Задача 10. Структура

```
ui_framework/
├── config/settings.py   настройки окружений (адрес, таймауты) из envs/<ENV>.env — pydantic-settings
├── application.py       фасад: раздаёт страницы — app.auth_page, app.dashboard_page
├── pages/               экраны целиком: BasePage, AuthPage, DashboardPage; шаги Allure на действиях
├── components/          куски экранов: формы (с логированием), таблицы, шапка, тост
├── fixtures/            pytest-фикстуры: app.py — пользователи и фабрики, data.py — тестовые данные
├── plugins/             pytest-хуки: reporting.py — окружение, URL и артефакты Playwright в Allure
├── data/                модели (OrderData) и генераторы (unique_email, isolated_price)
└── utils/               чистые функции без page: money.py, waiting.py
envs/                    docker.env, local.env, stage.env — адреса и таймауты окружений
tests/
├── conftest.py          pytest_plugins, хуки конфига и шапки, фикстуры settings / base_url
├── unit/                тесты утилит — без браузера
└── ui/                  UI-тесты; conftest.py — autouse-таймаут действий
```

Зависимости в одну сторону: tests → fixtures/plugins → application → pages → components → data/utils.

**Что было «не в ту сторону» и исправлено:**
- хуки отчёта (`reporting.py`) лежали в `fixtures/` — это не фикстуры; перенесены в `plugins/`;
- `data/generators.py` печатал 5 email при **импорте** (цикл `print` на уровне модуля) — побочный эффект
  у модуля данных; убран. Модуль с данными не должен ничего делать при импорте;
- email генерировался в двух местах (Faker в `fixtures/data.py` и `fixtures/app.py`) — теперь один источник,
  `data/generators.py`.

## Вопросы собеса

1. **Как устроен фреймворк.** Фреймворк отдельно от тестов. Конфиг окружений на pydantic-settings, окружение
   выбирается переменной `ENV`. Страницы — Page Object из компонентов, их раздаёт фасад `Application`.
   Фикстуры только готовят состояние и лежат плагинами во фреймворке, хуки отчёта — отдельным плагином.
   Модели и генераторы данных, чистые утилиты. Зависимости в одну сторону. Отчёт — Allure.
2. **Что в utils.** Только чистые функции, которые не знают про page и тесты: деньги, ожидание условия,
   форматирование. Признак — модуль можно взять в API-тесты без изменений. Не кладу: локаторы, «зарегистрировать
   и пополнить» (это фикстура), бизнес-проверки.
3. **Деньги.** Только `Decimal` из строки, никогда float. Ожидание форматирую так же, как сервер
   (`format_amount`), иначе `"100.50"` против `"100.5"`. Если вид не важен — сравниваю числа.
4. **Шаги и вложения.** `@allure.step` на методах PO и компонентов с подстановкой аргументов — шаги есть во всех
   тестах без дублирования; в тестах `with allure.step` для блоков проверок. Секреты в шаги не подставляю.
   Вложения — `allure.attach` / `allure.attach.file`.
5. **Скриншот упавшего теста.** Флаг pytest-playwright `--screenshot only-on-failure` (плюс `--tracing`,
   `--video`) кладёт файлы в `test-results/`; хук `pytest_runtest_teardown` с hookwrapper после teardown берёт их
   из `output_path` и прикладывает в Allure. URL — в `pytest_runtest_makereport`, пока страница открыта.
   xfail-тесты не считаются упавшими — артефактов у них нет.
6. **Зачем модели данных.** Сущность одним объектом с умолчаниями — тест задаёт только важные поля; производные
   значения (`cost`) считаются в одном месте; `frozen` защищает общие данные от изменений.
